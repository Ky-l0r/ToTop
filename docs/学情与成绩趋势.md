# 学情与成绩趋势

本文是「学情页」的实施依据，替代原「学情周报」的单页形态。周报 / 月报的周期概念取消，
页面改为「头卡 + 趋势 + 考试列表 + 概览 + AI 解读」五段纵向结构，全页只有一个时间维度。

实施约束沿用《架构设计》与《工程规范与构建说明》：无后端、数据不出设备、图表静态无动画、
页面内禁止写死色值。

## 一、定位与不做的事

学情页回答一个问题：**我最近考得怎么样，是在变好还是变差。**

不做的事（明确排除，避免功能蔓延）：

| 不做 | 原因 |
| --- | --- |
| 分数变化归因（涨落来自哪个知识点） | 学生直接看「多练的知识点」页，重复且不可避免地被误读为因果 |
| 过程趋势线（掌握度 / 正确率叠加） | 与「最近考试考得怎么样」不是同一个问题，同图会互相干扰 |
| 错因分布、复发 Top | 属于错题本范畴，学情页只陈述考试结果 |
| 提醒 / 通知 | 学生想学时自然会打开，不需要提醒 |
| 拍照识别分数 | 手动录入已足够，OCR 分数识别错误率与校验成本不划算 |
| 多目标 / 里程碑体系 | 每科一个目标 + 一个全局目标，够用 |

## 二、学期边界

学期由日期自动推断，不要求用户填写：

| 学期 | 区间 |
| --- | --- |
| 秋季 | 8 月 1 日 至 次年 1 月 31 日 |
| 春季 | 2 月 1 日 至 7 月 31 日 |

- 键：`2026S`（春）/ `2025A`（秋）；标签：`2026 春` / `2025 秋`。
- 允许用户修改本学期开学日（存 `settings` 键 `examTermStart`）。修改只影响**当前学期**的起点，
  历史学期不变，避免一条设置把整条时间轴挪位。
- 时间范围下拉只列学期，不提供「全部」：跨学期混排会让满分制、科目构成、竞争基数三件事同时失真。

## 三、数据模型

两张表，一次考试对应一个 `exam_session`，其下若干 `exam_score`。

```
exam_session  id / occurredOn / kind(minor·major) / name?
              gradeSize? / classSize? / gradeRank? / classRank?
              createdAt / updatedAt

exam_score    id / sessionId(FK, ON DELETE CASCADE) / subject
              score / fullScore / gradeRank? / classRank?
              unique(sessionId, subject)
```

约定：

1. `occurredOn` 为 UTC 日序号，与 `daily_stats.date` 同口径，展示层自行转时区；
2. **人数整场共用**，存在 `exam_session`，不冗余到科目（同一个班、同一个年级，整场人数当然一致）；
3. 排名分级：科目级排名存 `exam_score`，总分排名存 `exam_session`；
4. 外键级联删除：删一次考试连带删该场全部科目，二次确认必须说明将删除几条科目记录；
5. 名称为空即空，不显示占位、不显示日期。

## 四、口径

### 4.1 得分率

```
得分率 = 得分 / 满分 × 100
```

`满分 <= 0` 或得分缺失视为不可计分，不参与任何平均，折线上留断点而不是画 0。

### 4.2 单科视图

选某一科时：取该科全部场次（小考大考都算），得分率 = 该科得分 / 该科满分。
折线点数 = 该科有记录的场次数。

### 4.3 全部科目视图

**只画「设置中勾选的科目全部录入完成」的场次**，得分率为各科得分率的**等权平均**（不用总分加权）。

- 为什么要过滤：每次考试的科目数不同，若混在一起，一次只考两科的场次会与六科场次同图比较，折线必然乱跳；
- 为什么等权：150 分制与 100 分制科目在「学习水平」上应当同权，加权会让高分科目主导；
- 小考通常只考一两科，天然进不了该视图——「全部里主要看大考」是这个规则的**自然结果**，不需要额外分支；
- 一个完整场次都没有时，给引导文案，不画空折线；
- 勾选科目变化会重算完整场次集合（依赖当前勾选，不是历史快照），需在文档与界面上说明。

### 4.4 排名语义

| 视图 | 排名来源 | 文案 |
| --- | --- | --- |
| 全部科目 | `exam_session` 总分排名 | 「这次考试：年级 56 / 480」 |
| 单科 | `exam_score` 该科排名 | 「数学：年级 12 / 480」 |

学校给的排名是**这次考试的名次**，不是每科分别给；单科排名需要学生自己额外填（选填）。
文案必须写清是「这次考试」还是「数学」，同一个位置两种数字串台是最容易出的错。

百分位 = `排名 / 人数 × 100`，显示「前 12%」；人数缺失时只显示名次，不编造百分位。
年级为主、班级为辅。

### 4.5 X 轴

按「第几次」等距，排序按真实日期升序。原因：一学期十几次考试，按真实日期排会在假期处留出大片空白，
而学生关心的是「每次考成什么样」，不是间隔多久。

### 4.6 大考与小考

- 同一张图、同一条折线，不拆两条；
- 大考实心点并标注名称，小考空心小点不标注；
- 筛选（全部 / 大考 / 小考）入口放在趋势卡右上角，默认全部。

## 五、录入

一次录一整场，多科同表，不分多次。

```
日期 / 类型（默认小考）/ 名称（可空）
科目多选（默认 = 设置中勾选的科目，勾几科出几行）
   科目   得分   满分
排名（选填，默认收起）展开后：
   科目   班级排名   年级排名
   总分   班级排名   年级排名（只录一科时整行隐藏）
```

- 满分按科目预填（语数英 150，其余 100），可改；
- 班级人数 / 年级人数从设置带出，录入页只显示「班 45 · 级 480」，点开可改并写回设置；
- 所有排名字段允许留空，之后通过列表项补填；留空不阻塞保存；
- 校验：`0 <= 得分 <= 满分`、`满分 > 0`、`1 <= 排名 <= 人数`、同场次科目不重复。

## 六、目标分

每科一个目标 + 一个全局目标（均按得分率百分比）。头卡显示进度条与「按当前趋势还差几次」，
不设提醒、不设阶段里程碑。达成估算仅在 ≥4 个数据点时显示，避免两个点就预测人生。

## 七、AI 解读

- **手动触发**，进页面不自动调用；关闭时页面照常可用，0 token；
- 输入是本地已算好的结构化摘要 JSON（场次、得分率、排名、变化量），数字由模板渲染，AI 只写文字；
- 输出约束：约 200 字、**只给正向建议、不做负面评价、不点名知识点**、不得改写或新增任何数字；
- 失败降级为纯数据版，并给出可读原因；每次调用写 `ai_trace`。

## 八、UI 约定

| 项 | 规则 |
| --- | --- |
| 卡片 | 统一 `SectionCard`（白底、12dp 圆角、14dp 内边距），与报告页共用一份实现 |
| 颜色 | 主色 `Tokens.Primary`；进度未达成为主色，达成为 `Tokens.Success`；不使用股市红涨绿跌 |
| 图表 | Canvas 静态一帧、无动画、点数 ≤ 60，不引第三方图表库 |
| 控件 | 顶部两个下拉（科目、学期），趋势卡内一个筛选下拉；不使用 TabRow |
| 空态 | 无记录 / 无排名 / 无完整场次 / 加载失败，四种都有可执行文案 |
| 文案 | 只陈述事实，不评判学生 |
