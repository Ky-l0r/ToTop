# 工程规范与构建说明

本文档由 M1 里程碑建立，记录工程骨架的构建约定。后续里程碑不得修改本章列出的版本与结构，
确需变更时须在 CHANGELOG 记录原因，并同步更新本文件。

> **适用范围**：第一章至第九章描述 Android 原生工程（1.0 起位于 `legacy/android/`，已冻结）。
> 1.0 的 UniApp 双端工程见第十章；搬迁完成后第一至九章随原生工程一并归档。

## 1. 环境要求

| 项目 | 版本 | 说明 |
| --- | --- | --- |
| JDK | 17 | 编译目标与 Gradle 运行环境均为 17；更高 JDK 亦可运行 Gradle，但 jvmTarget 固定为 17 |
| Gradle | 8.7 | 由 gradle/wrapper/gradle-wrapper.properties 固定 |
| AGP | 8.5.2 | 见 gradle/libs.versions.toml |
| Kotlin | 1.9.24 | 与 Compose Compiler 1.5.14 配套 |
| Android SDK | compileSdk 34 / build-tools 34.0.0 | minSdk 24，targetSdk 34 |

## 2. 首次构建

1. 复制 local.properties.example 为 local.properties，填写本机 sdk.dir。
2. 执行 ./gradlew :app:assembleDebug。
3. 产物位于 app/build/outputs/apk/debug/app-debug.apk。

local.properties、签名文件与密钥一律不提交，.gitignore 已排除。

## 3. 版本目录规则

- 全部依赖版本集中在 gradle/libs.versions.toml，模块脚本内禁止出现硬编码版本号。
- 本文件由 M1 一次性列全，覆盖 M1-M8 全部里程碑所需依赖。
- 新增依赖时：先在 [versions] 增加版本键，再加 [libraries] 别名，最后在 app/build.gradle.kts 引用。

## 4. 模块结构

单模块 app，包名 com.totop.app，按《AI 辅助学习 App 开发方案》2.3 节组织：

    com/totop/app/
      App.kt                  Hilt 应用入口
      MainActivity.kt         唯一 Activity，UI 全部 Compose
      navigation/             路由常量、底部导航、导航宿主
      ui/                     Compose 页面，页面一律以 Screen 结尾
        theme/                色彩、排版、主题
        components/           可复用组件
        solve/ mistakes/ knowledge/ study/ reviewmaterial/ hub/ companion/ settings/   功能页面
      domain/                 model 与 algorithm（纯 Kotlin，可单测）
      data/                   local(Room) / remote(LLM) / repo / prefs
      ml/                     OCR、图片预处理、模型路由、TTS
      work/                   WorkManager 任务
      util/                   导出、备份、公式渲染等工具

## 5. 导航路由

| 路由 | 页面 | 层级 | 进入方式 |
| --- | --- | --- | --- |
| solve | SolveScreen | 顶层 | 启动页与底部栏 |
| mistakes | MistakesScreen | 顶层 | 底部栏 |
| knowledge | KnowledgeScreen | 顶层 | 底部栏 |
| report | StudyScreen | 二级 | 功能中心「学情」 |
| settings | SettingsScreen | 顶层 | 底部栏 |
| kpoint_detail/{kpointId} | KnowledgePointDetailScreen | 二级 | 知识点处点击 |
| review | ReviewScreen | 二级 | 错题本进入复习 |
| backup | BackupScreen | 二级 | 设置进入备份 |
| review_material | ReviewMaterialScreen | 二级 | 功能中心 / 首页进入 |
| review_material_detail/{createdAtUtc} | ReviewMaterialDetailScreen | 三级 | 资料列表点历史 / 生成成功自动进入 |

参数约定：因 minSdk 24，不使用路由级对象序列化，统一走字符串路径参数；
kpointId 必须是内置知识点树的受控 ID（例如 KP_MATH_0312），AI 不得自造。

## 6. 性能与合规约定

- 不使用毛玻璃（高斯模糊）、视差、大面积弹性动画；底部栏不做出现动画。
- 不启用动态取色，主题固定，保证各机型一致且零额外计算。
- 不使用 XML View，不引入统计、广告、埋点 SDK。
- 代码与文档禁止使用 emoji。
- 页面离开必须取消网络请求（M2 起），所有 AI 调用须写 ai_trace。

## 7. 打包与包体

- 仅打包 arm64-v8a（abiFilters），首次安装包体积已按 30MB 门禁控制。
- release 开启 R8 与资源压缩，ProGuard 规则保留 kotlinx.serialization、Retrofit、Hilt、Room、ML Kit 契约。
- 已配置 Baseline Profile 依赖（androidx.profileinstaller），M8 生成实际 profile 文件。
- 网络默认仅允许 HTTPS；明文仅为 localhost、127.0.0.1、10.0.2.2 放行，用于本地 Ollama 端点。

## 8. Kotlin 编译策略

gradle.properties 中固定 kotlin.compiler.execution.strategy=in-process。
原因：部分受限环境与 CI 沙箱无法建立 Kotlin 编译守护进程的本地连接，进程内编译可稳定完成构建。
若本机编译速度受影响，可在个人环境覆盖该值，但不得提交修改。

## 9. CI

- .github/workflows/ci.yml：PR 触发，执行 gitleaks、lint、单元测试与 assembleDebug。
- .github/workflows/release.yml：打 tag 触发，写入密钥后构建 release APK 并校验 30MB 体积门禁，上传到 Release 附件。
- 1.0 起需新增一条针对 `apps/mobile/` 的流水线，见 10.6；两条流水线按改动路径触发，互不阻塞。

## 10. 1.0 双端工程（UniApp）

### 10.1 目录

    legacy/android/        0.8.0 原生工程，冻结，只修致命缺陷
    apps/mobile/           UniApp 工程，1.0 唯一交付物
      src/pages/           页面，一个目录一页
      src/components/      组件（相机、裁剪、公式、题目卡）
      src/stores/          Pinia，一页一 store
      src/styles/          design token，唯一定义处
      src/locales/         用户可见文案
      src/platform/        条件编译与原生能力桥接
    packages/core/         纯 TS 领域层，禁止 import uni

### 10.2 环境

| 项 | 要求 | 说明 |
| --- | --- | --- |
| Node | 20 LTS 起 | 与 vite 5.2.8 配套；本机实测 v22.22.2 通过 |
| 包管理 | pnpm 12，workspace | 三棵树共用一个 lockfile；pnpm 12 起依赖安装脚本默认不执行，需在 `pnpm-workspace.yaml` 的 `allowBuilds` 里逐包表态（当前只放行 esbuild） |
| 构建 | Vite | 不引入 webpack 老链路 |
| 端打包 | 云打包或本地 HBuilderX | 二选一，写进 README，不要两套并存 |

测试用 **Node 内置的 `node:sqlite`**（Node 22.5 起），不引 better-sqlite3 这类原生依赖：
迁移的正确性全在 SQL 上，用真实 SQLite 引擎跑，装上来的代价只是一个实验性警告。

`@types/node` 必须与运行时**同一个大版本**（当前 22.x）。装 26.x 会让 TS 4.9 解析不了它的声明
（`ffi.d.ts` 用了新语法），整个 core 的类型检查直接崩。

版本号一律写在根 `package.json` 与 `pnpm-lock.yaml` 里，子包不得各自固定版本
（对齐旧树"依赖只在 libs.versions.toml 增改"的规矩）。

本机 `registry.npmjs.org` 会挂起不返回，安装时加 `--registry=https://registry.npmmirror.com`。
**不要把 registry 写进仓库的 `.npmrc`**：那是本机网络问题，不是工程配置，写进去会把所有人绑到同一个镜像。

### 10.3 构建与验证命令

以 `apps/mobile/package.json` 的脚本为准，本文件只规定必须具备哪几条能力：

| 能力 | 用途 |
| --- | --- |
| 类型检查 | CI 与提交前必跑，等价于 `ktlintCheck` 的位置 |
| lint | 风格与潜在缺陷，规则里必须开启"禁止 any" |
| 单元测试 | 跑 `packages/core`，Node 环境，不依赖模拟器 |
| 双端构建 | Android 与 iOS 各一条，产出可安装包 |

**不写死脚本名**：脚本改名时本文件不该跟着改，只有"必须具备这四条"是规范。

已实跑的命令（2026-11-19，Windows / Node 22.22.2 / pnpm 12.14.0）：

    pnpm install --registry=https://registry.npmmirror.com
    pnpm run check          # 类型检查 + lint + 单测，一条命令跑完

分项命令（排查时用）：

    pnpm run typecheck      # 两个包的类型检查
    pnpm run lint           # eslint 全仓扫描
    pnpm run test           # packages/core 的 vitest（真实 SQLite，不是 mock）
    pnpm --filter @totop/mobile run build:h5

领域层的单测放在 `packages/core/test/`，`pnpm --filter @totop/core run test` 单跑。
表结构与迁移的用例**读 `app/schemas/` 下的 Room 快照**来搭"旧库"，不手抄 DDL：
手抄的那份迟早与真实结构不一致，测试就变成了验抄写。

`dev:app` / `build:app` 指向 `uni -p app`，**本机未验证**——端上构建需要 HBuilderX 或云打包环境，
属 T13。

**TypeScript 版本钉在 4.9.4，全仓一个版本。** 原因：`typescript-eslint` 8.x 明确拒绝 TS 7
（报 `typescript-eslint does not support TS 7.0`，lint 会直接退出），而 uni-app 官方模板本身
用 4.9。升级 TS 必须同时确认 typescript-eslint 与 vue-tsc 都支持，不许只升根 `package.json`。

**lint 的两条约定**：`@typescript-eslint/no-explicit-any` 为 error（模型 JSON 必须过运行时校验，
`any` 等于把校验关掉）；`vue/multi-word-component-names` 只对 `pages/` 豁免——页面入口按 uni-app
约定叫 `index.vue`，组件目录仍受约束。

### 10.4 双端打包与体积

| 端 | 门禁 | 说明 |
| --- | --- | --- |
| Android | 安装包 ≤ 80MB | 0.8.0 的 30MB 是单 ABI + 全 R8 的结果，双端框架自带运行时后不适用 |
| iOS | 归档后 ≤ 120MB | 含 WebView 与公式资源 |

体积只写进 `docs/构建与验证清单.md` 并标注测量日期，不要写在这里当固定值。

### 10.5 与旧树的边界

- 新增文件只进 `apps/mobile/` 与 `packages/core/`，不许往 `legacy/android/` 加功能。
- 原生版必须保留"导出全部数据"，它是老用户迁移的唯一通道。
- 平台差异只在 `src/platform/` 与条件编译块里出现，业务代码里不许出现 `if (android)`。

### 10.6 CI 补充

1.0 需要三条流水线，按路径触发：

| 流水线 | 触发路径 | 内容 |
| --- | --- | --- |
| android-legacy | `legacy/android/**` | 沿用现有 Gradle 门禁 |
| mobile | `apps/mobile/**`、`packages/core/**` | 类型检查、lint、单测、双端构建 |
| docs | `docs/**`、`*.md` | emoji 检查、链接检查 |

原有两条工作流在搬迁期间保留，搬迁完成后 `legacy` 那条改为仅手动触发。
