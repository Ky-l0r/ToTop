# 0.4.0 待决策项（2026-10-28 记录）

本轮 10 条反馈中，以下各点在需求上存在**多种合理解法**，或缺少可依据的口径。
按约定「先跳过并记录」，代码里只做了最小、可回退的实现，等明确后再改。

已完成的实现都在 `docs/偏离记录.md` 第 17 节，本文件只列需要你拍板的部分。

## 1. 「我已理解」之后要发生什么

现状：按钮出现在「已有解答 + 最后一条是正常结束的 AI 回复」时，点击 = 新建对话
（归档当前会话、清空输入区），与顶部「+」的清理逻辑完全一致。

待定：

| 选项 | 代价 | 影响 |
| --- | --- | --- |
| A. 只新建对话（当前实现） | 0 | 学生要自己再拍下一题 |
| B. 新建对话并直接打开相机 | 小 | 少一次点击，但「想先歇一下」的人会被强制跳转 |
| C. 顺带把这道题标记为「已掌握」 | 中 | 需要新的掌握度口径（当前掌握度只由错题与提示记录推导，不能由学生自评决定），会与 `MasteryCalculator` 的既有公式冲突 |
| D. 新建对话并给一张「下一题」入口卡片 | 中 | 需要有推荐来源，否则只是把首页搬过来 |

另一个未定的点：**只有一轮解答、没有任何追问时，要不要显示这个按钮**。
现在的实现是「只要答完就显示」，因为无法判断学生是否通过对话确认了理解
（模型没有「确认理解」这个输出字段）。

## 2. 补拍修正了题干之后，错题本要不要跟着改

现状：补拍的照片只进入当前会话（视觉模型据此修正理解），
`question.stemText` / `mistake_record` 仍是**首次解答时落库的那一份**。

待定：

- A. 保持现状（补拍只影响对话）——简单，但错题本里的题干可能仍是错的；
- B. 补拍后重新跑一次阶段 A，更新题目与错题记录——要处理「同一条错题被改两次」的去重与复发计数；
- C. 只在会话里提示「已按新照片理解，但错题本未更新」。

## 3. 语音输入的形态

现状：系统 `SpeechRecognizer`（`RecognizerIntent`，zh-CN，部分结果实时回填），
点一次开始、再点一次结束。免第三方 SDK、免额外费用。

待定：

- 是否需要「按住说话、松手结束」的交互（现在是一键开关）；
- 是否需要允许用户选择识别引擎（部分机型自带引擎中文识别明显更好）；
- 是否接受「部分机型的中文识别需要联网」这一限制（本应用其余功能可以纯离线阅读）。

## 4. 启动动画的具体形态

现状：图标 + 「To Top」+ 一句话，420ms 从 0.92 放大到 1.0 并淡入，
最短展示 620ms，之后 260ms 淡出到首页。

「此前要求的启动动画」没有留在仓库里的文字依据（`CHANGELOG` 只记录了系统 splash
背景色修复），因此这里是按「轻、快、不遮挡真实加载」自行定的。

待定：是否需要特定的品牌动效（例如图标描边、字标逐个出现）、
是否需要在设置里提供「关闭启动动画」开关（低端机/无障碍场景）。

## 5. 输入区布局：拍照与相册合并成一个「+」菜单

现状：左侧「+」展开菜单（拍照 / 从相册选），输入框内右侧是麦克风，最右是发送。
一行里的可点元素从 5 个降到 3 个，输入框宽度回到主位。

待定：拍摄是最高频动作，收进菜单后**多一次点击**。
如果你更看重「一步到位」，可以改回「相机图标常驻 + 相册进菜单」。

## 6. 框选相关的两处延伸

现状：框选坐标改为按图片绘制区域（Fit 后的矩形）归一化；
裁剪结果会落盘成 `filesDir/images/<sha256>.jpg`，会话气泡与错题本都显示裁剪图。

待定：

- 错题本详情页是否也提供「重新框选」入口（目前只能在拍题页框）；
- 多页题目在错题本里只保留了第 1 页（既有取舍，见偏离记录 14.x），是否需要保留全部页。

## 7. 页面过渡动画的实测

现状：进入 180ms、退出 120ms 的淡入淡出 + 屏宽 1/18 的横向位移。

在低端机上是否真的「不增加明显开销」需要真机验证（本环境没有设备）。
若出现掉帧，最快的回退是把位移去掉、只保留淡入淡出（改 `NavGraph.kt` 的四个 transition）。

## 8. 待真机验证的清单

- 新建对话后连续提问 3 次，确认每次都有输出（本轮修的是注册表被永久封存，属于确定性缺陷，但仍需在真机复现一次）；
- 框选一小块题目后，会话气泡里的图应当只剩框内内容；
- 语音输入在无 Google 服务的国产 ROM 上的可用性与错误提示；
- 首页 -> 拍题 -> 二级页 来回切换的掉帧情况。
