# 实现偏离记录

本文档记录实施过程中与原方案（《AI 辅助学习 App 开发方案》）不一致的地方及原因。
依据方案 12.1 第 10 条与文末约定：遇未覆盖细节按「本地优先、成本最低、低端机友好」决策；
偏离必须显式记录，不得静默省略。

## 1. Kotlin 1.9.24 -> 1.9.25

- 原方案：Kotlin 1.9+
- 实际：1.9.25（KSP 1.9.25-1.0.20，Compose 编译器 1.5.15）
- 原因：1.9.24 的 JVM 后端在本项目 LlmClient（挂起函数 + channelFlow + 内联 lambda + 循环 break 组合）上必然抛
  AnalyzerException / NPE，编译无法通过；该问题在上游 1.9.25 已修复。1.9.x 补丁线内 API 一致，无迁移成本。
- 记录位置：gradle/libs.versions.toml 顶部注释

## 2. 公式渲染：KaTeX 官方包 -> 自研轻量渲染器兜底

- 原方案：KaTeX 0.16.x 离线内置于 assets/katex
- 实际：assets/katex 内置自研 totop-latex.min.js / .min.css（覆盖分式、根号、上下标、希腊字母、函数名、\left\right 等子集）
- 原因：构建环境完全离线，无法获取 KaTeX 官方分发包
- 明确约束：**不是 MathJax**（方案 2.2 明确禁止 MathJax）
- 补齐方式：见 app/src/main/assets/katex/README.md，放入官方 katex.min.js/css/fonts 即可，
  宿主页 formula_render.html 自动优先使用官方 KaTeX，**无需修改任何 Kotlin 代码**
- 登记要求：补齐后须在 THIRD_PARTY.md 登记 KaTeX 的 MIT 许可

## 3. 图表渲染：WebView + ECharts -> Compose Canvas

- 原方案：Vico 或 WebView + ECharts(canvas)
- 实际：Compose Canvas 静态绘制（KnowledgeChartViews），数据装配在纯函数 KnowledgeCharts
- 原因：仓库无 echarts 资源且环境离线不可下载；Canvas 方案同样满足方案 7.1 全部硬约束
  （只在 canvas 绘制、无动画、无实时力导向、数据点降采样 <= 60）
- 可替换性：补齐 echarts.min.js 后只需替换 KnowledgeChartViews 的绘制函数，数据层无需改动
- 影响范围：ui/knowledge 的雷达图、趋势折线、错因饼图（章节热力列表本就是原生列表）

## 4. Anki 导出：APKG -> TSV

- 原方案：Anki 卡片导出，APKG 库体积过大则退化为 CSV 并说明
- 实际：直接导出 Anki 可直接导入的 TSV（首行 #separator:tab / #html:true / #columns:正面,背面）
- 原因：生成 .apkg 需引入第三方集合格式库，违反「不新增 SDK」与 30MB 包体门禁；
  TSV 是 Anki 官方支持的导入格式，功能等价

## 5. 周报「复习完成率」的待复习口径

- 方案未定义「待复习」的精确 SQL 口径

- 理由：符合方案 C4「无正确率、无判卷」与「全部统计口径建立在错题侧」的产品哲学

## 11. 模型接入修复（本轮）

### 11.1 连通性校验在主线程阻塞 I/O（已修）

- 现象：设置页「测试连接」必报「未归类问题 · 调用模型时发生未预期的问题」，且提示里没有 HTTP 状态码。
- 根因：`LlmClient.probe()` 内部调用 `performProbe()`，后者走阻塞式 `Call.execute()`；
  而 `SettingsViewModel.testConnection()` 在 `viewModelScope`（Main.immediate）中调用它，
  且 `probe()` 未切 `Dispatchers.IO`（同文件的 `stream()` 有 `.flowOn(IO)` 保护，probe 漏了）。
  系统抛 `NetworkOnMainThreadException`，异常发生在发出请求之前，因此永远没有 HTTP 码，
  最终落入 `LlmError.Unknown` 被显示为「未归类问题」。
- 修复：`probe()` 内包 `withContext(Dispatchers.IO)`；并新增 `LlmError.NetworkOnMainThread` 专项分类，
  让同类缺陷以后能被明确指认，而不是继续伪装成未知错误。
- 单测为何没发现：`LlmClientMockWebServerTest` 跑在 `runTest`（测试调度器），
  主线程检查不生效。已补充 `LlmProbeContractTest` 覆盖新契约。

### 11.2 探测请求形态不适合思考模式模型（已修）

- 原实现：非流式 + `max_tokens=8`。
- 问题：思考模式默认开启且思考链与正文共享 `max_tokens`，8 个 token 连思考链都开不了头，
  正文必然为空；部分厂商（如百炼）还明确拒绝非流式调用思考模式模型。
- 修复：改为**流式** + `max_tokens=64` + 显式 `thinking: disabled`。
- 附带修掉一个「伪造成功」缺陷：原实现只要拿到 usage 就判成功，正文全空也会显示连接成功。
  现在正文为空一律判失败，并区分「被截断」与「只吐了思考链」两种成因。

### 11.3 「阶段 B 输出为空」（已修）

- 现象：解题走到阶段 B 报「模型返回的内容不是约定的 JSON 结构…阶段 B 输出为空」。
- 根因三条叠加：
  1. `Wire.kt` 只解析 `delta.content`，完全丢弃 `reasoning_content`，思考模式下的正常响应被当成没输出；
  2. `finish_reason` 被完全忽略，无法区分「模型截断」与「模型拒绝输出」；
  3. 四阶段强制 `json_object` + 简洁档 `max_tokens=1024`，预算被思考链吃光。
     DeepSeek 官方 JSON 模式文档亦写明「有概率返回空的 content」。
- 修复：新增 `LlmChunk.Reasoning` 单独通道；透传并判定 `finish_reason=length`；
  默认关闭思考模式，遇「参数不支持」自动逐级降级重试；`max_tokens` 提升到 2048 / 8192。

### 11.4 错误分类从 11 类扩到 18 类

新增：`ModelNameInvalid`（覆盖 400 语义的模型不存在）、`ParameterNotSupported`、
`ImageInputNotSupported`、`ImageFormatRejected`、`ContextLengthExceeded`、
`EmptyCompletion`、`NetworkOnMainThread`。

补充 400/422 的语义分流：部分厂商（如阿里云百炼）用 **400 + invalid_parameter_error**
表达「模型不存在」而不是 404，旧代码只认 404，于是这类失败全部掉进兜底分类。
现在按响应体关键词分流，并在模型名错误时调用 `GET /models` 列出可用模型。

### 11.5 厂商模板修正

- DeepSeek 模板的 `visionModel` 原为 `deepseek-chat`，注释写「当前无视觉模型」——该信息已过期。
  `deepseek-flash` 官方支持图像理解（JPEG/PNG/GIF/WebP，单请求最多 600 张、64MiB）。
  错误模板会让含图题目静默走到不支持视觉的模型上。
- 新增「阿里云百炼（DeepSeek 模型）」模板：百炼的模型 ID 是 `deepseek-v4.1-flash`，
  与 DeepSeek 官方的 `deepseek-flash` 不同，混用会得到 400 Model not exist。

| 项 | 原状 | 现状 | 取舍说明 |

| 底部导航 | 5 项 | **3 项**（首页/拍题/功能中心） | 原有 5 个路由全部保留，改为从功能中心进入，不丢可达性 |

### 12.1 框选策略：本地裁剪后上传（而非上传原图 + 坐标）

理由：
1. OpenAI 兼容协议**没有标准的坐标字段**，各厂商互不支持，传了也不保证生效；
2. 只传裁剪图能明显降低 token（一道小题通常只占整页的一小块）；
3. 识别质量更高，页眉与其它题目不会干扰模型。

坐标以**归一化矩形**（0..1）落库，与原图像素尺寸解耦，日后换分辨率仍能还原选区。

### 12.2 多页题目：多图直传，降级路径保留

DeepSeek 官方限制为单请求最多 600 张图 / 64MiB，多页题目远低于该上限，
因此**默认多图直传**，并在每张图前插入「这是同一道题的第 i/N 页」说明。
若厂商返回图片相关的 400，则判为 `ImageInputNotSupported` 并明确提示用户，
保留「逐页识别后合并」的降级空间，绝不静默失败。

### 12.3 分科目：JOIN 查询，零迁移

`mistake_record` 本身没有科目标识，科目在 `question.subject` 上。
采用 `JOIN question` 聚合，**不改表结构、不写 Room 迁移**，
因此不会触碰任何既有用户数据，也不可能因迁移失败丢错题。

### 12.4 复习资料 PDF：原生 PdfDocument 排版

使用 `android.graphics.pdf.PdfDocument` 直接排 A4（595×842pt），
不引入 WebView/HTML 模板或第三方 PDF 库，符合「零新增 SDK、离线可用」约束。
未选中框选区域时的像素换算改为纯数据类 `PixelRect`，
因为 `android.graphics.Rect` 在 JVM 单测（isReturnDefaultValues=true）下所有方法返回 0，
会导致该段逻辑无法被有效验证。

## 13. 第二轮修复（真机反馈驱动的缺陷修正）

本轮所有改动都来自真机截图暴露的实际问题，不是推测。

### 13.1 解题「阶段 D 失败」的真实原因：把正确行为当成了故障

真机报错是「契约字段缺失：studentSteps、knowledgePoints」。
排查后发现这是**校验逻辑写错了**，不是模型出错：

- 用户没填解题过程时，阶段 C 依契约返回 `firstError: null` 与空 `studentSteps`，
  这是提示词里明确规定的**正确行为**；
- 非数学科目（化学等）没有内置知识点树，候选清单为空，
  阶段 D 必然返回空 `kpoints`，同样是正确的；
- 但旧 `missingStructure()` 把这两项算作「契约缺失」，直接判整次失败。

后果是：**不填解题过程永远解不出题；任何非数学题永远解不出题**。

修正：
1. `missingStructure()` 只保留 `question` 与 `standardSolution`（缺这两项结果毫无价值）；
2. 新增 `missingOptionalStructure()`，把 `studentSteps` 与 `knowledgePoints` 的缺失降级为告警；
3. 候选清单为空时**跳过阶段 D 调用**，直接构造合法的空 kpoints 结构，
   并在 UI 明确显示「暂无该科目的知识点树」——跳过是显式的，不是静默降级。

### 13.2 失败阶段号误报

合并四阶段结果时的校验失败，旧实现把 `stage` 置为 D，
于是任何合并问题都显示成「阶段 D · 知识点抽取」失败，
掩盖了真实原因（例如实际是阶段 C 输出为空）。现在合并阶段不再冒充某个具体阶段。

### 13.3 拍题页「没变化」：组件写了但没接线

上一轮新增了 `CaptureScreen`（全屏相机 + 圆形快门）、`CropOverlay`（框选）、
`PagePreviewScreen`（多页缩略图），但 **`Routes.SOLVE` 仍然指向旧的 `SolveScreen`**，
所以用户看到的还是卡片堆叠式表单。这是上一轮的真实疏漏。

修正：
1. 新增 `SolveRoute` 作为容器，在「对话页 / 全屏相机 / 单页框选」三个互斥界面间切换；
2. 导航图改指向 `SolveRoute`，并**删除旧 `SolveScreen`**（同时留两套会让后续改动分叉）；
3. 多页支持贯穿到数据层：`PreparedQuestion.pages` 取代单张 `imagePath`，
   逐页按框选裁剪后一起上传。

### 13.4 改为对话式 UI

按需求对齐主流对话式 AI 的布局习惯（只借鉴交互组织方式，不使用任何第三方素材）：

- 底部是输入框，**图片在输入框正上方**的同一容器内；
- 输入框用于写**解题思路**，不是写题干；
- **不再显示 OCR 识别文本**——识别结果只作为路由判断输入，
  展示出来既占屏又让用户困惑「这串乱码是什么」；
- 阶段进度压成一行文字，不再是整张卡片；
- 解题结果按「标准解 → 错因 → 考点」合成三条助手气泡，替代原先十几个卡片。

### 13.5 「命中缓存 0 token」与首字耗时不再展示

这两个都是内部实现细节。用户看到「命中缓存 0 token」只会疑惑「为什么没联网」，
首字耗时则是性能自检指标，属于开发者关心的事。现在阶段行只显示对用户有意义的结论。

### 13.6 页面切换卡顿

主因是 Compose Navigation 的默认过渡动画（淡入 + 位移）：
目标页面在动画期间正好在做数据库查询（错题数、知识点分布、复习计划），
低端机上表现为「点了没反应，然后突然跳过来」。

修正：
1. 四条导航过渡全部设为 `None`（也与项目「禁止大面积动画」规范一致）；
2. 点击当前页直接返回，不做无意义的出栈入栈；
3. 顶层跳转改用 `findStartDestination()`，避免嵌套图时 `popUpTo` 失效导致栈增长。

### 13.7 深色模式默认关闭

需求要求「淡紫主色 + 白色背景」，但主题原先跟随系统——
系统处于深色模式的手机打开本应用会整体变黑，与要求正好相反。
现在默认固定浅色（仍保留 `darkTheme` 参数以便单独验证深色配色）。

### 13.8 补齐上一轮未完成的两处

1. **离线记题**：上一轮是空壳（永远显示「还没有记录」）。
   现新增 `OfflineNoteRepository`（本地 JSON + 原子写入 rename），
   拍题页「先记下来（不联网）」真实落盘，列表可查看与删除。
   选文件而非 Room 表，是为了**零迁移**——新增表要升 version、写 Migration、补迁移测试，
   而这类临时草稿数据不参与任何跨表查询。
2. **复习资料**：上一轮只生成本地骨架，未接模型。
   现新增 `ReviewMaterialGateway`，把用户**真实错过的题**作为原料交给模型，
   返回严格校验过的结构化资料。典型错题直接用本地数据，不交给模型复述
   （模型措辞可能把题干改错，而这些题用户自己认得出来）。

### 13.9 测试语义同步更新

以下两处测试断言的正是本轮废除的旧行为，属于**有意的行为变更**，测试随语义更新：

1. `AiSolveResultContractTest`：空 DTO 的缺失项由四项改为两项，并新增两条用例
   （没有学生过程、知识点为空都不算致命缺失）；
2. `SolveQuestionUseCaseTest`：「DTO 结构缺失时拒绝入库」改为「标准解答缺失时拒绝入库」，
   并新增「没有学生步骤时仍正常返回标准解答」。



## 14. 第二轮真机反馈的修复与偏离

### 14.1 框选交互改为「松手保留 + 可再调」

原实现用 `pointerInput(Unit)`，手势 lambda 只创建一次，闭包捕获的是首次组合时的
`rect`（几乎总是 null）。于是 `onDragEnd` 里读到的永远是 null，
判定「没框或框太小」后立刻回调 `onRectChanged(null)`——用户看到的就是「一松手框就没了」。

现改为：拖动过程只维护**本地像素矩形**，松手时才用本地结果提交；
`pointerInput` 以 `rect` 为 key 重建，保证读到最新选区。
同时支持拖四角调整与拖内部平移，并在选区外压暗、四角画把手，
让「框到哪儿了」这件事有明确视觉反馈。

### 14.2 框选预览改用高清图而不是缩略图

原实现把列表缩略图（长边 320）当作框选背景，铺满全屏后完全看不清行。
现单独解码长边 1280 的预览图（`PREVIEW_LONG_SIDE`），与上传图同分辨率，做到所见即所得。
取舍：内存占用比缩略图高一档，但 1280 长边在低端机上解码一次约 4MB 级，
且只在框选页存在期间保留，退出即释放。

### 14.3 拍摄流程改为「拍 -> 框 -> 写思路 -> 发送」

原流程拍完直接回到对话页，甚至直接发送，跳过了框选与写思路两步。
现流程：

```
拍照/相册 -> 自动进入框选页 -> 确认 -> 回到对话页 -> 写思路 -> 发送
```

`确认` 按钮的语义刻意改为「回到对话页」而不是「开始解题」：
要不要解、思路写没写，由用户自己决定，而不是拍完就替他提交。

### 14.4 会话持久化：文件而不是 Room 表

多对话管理需要持久化整段消息历史。选文件（`filesDir/sessions/*.json`）而不是新增 Room 表，
理由与离线记题一致：**零迁移**。新增表要升 DB version、写 Migration、补 MigrationTest，
而会话不参与任何跨表 JOIN 或聚合统计，一条会话整体读写的场景用文件反而更简单。

原子性：先写 `.tmp` 再 rename；单条会话损坏时跳过它继续解析其余，
不让一条坏数据毁掉全部历史。

### 14.5 追问不重跑四阶段

旧实现每次发送都重跑整套四阶段流程，得到一套全新解答——这正是「我问的是追问，
它却重新输出一遍」的成因。

新增 `FollowUpGateway`：把上一轮的结构化简答题干、已知、所求、标准步骤、
最终答案、错因压成一段上下文文本，连同用户本次追问一起发给模型，
要求「回答这个具体问题，不要重讲整道题」。

判定规则简单可预测：当前会话里**已经有解答**就走追问，否则走四阶段。

### 14.6 错题本与薄弱知识点不同步的两个根因

1. `persist` 在 `firstError == null` 时整体 `return`——没定位到错因就什么都不存。
   而「学生没写解题过程」时阶段 C 按契约返回 `firstError = null`，
   于是这类题永远进不了错题本。
   现改为：题目**总是**保存；有错因写完整记录，无错因也写一条待复习记录
   （错因归到固定七类的兜底项，解释里注明原因）。
2. 掌握度只由每日 Worker 更新，当天解题后「还需要多练的知识点」永远是空的。
   现新增 `MasteryRecorder`，落库后立即重算相关知识点，与每日 Worker **共用同一套公式**
   （直接调用 `MasteryCalculator`，绝不写第二套）。

### 14.7 知识点树扩到十科时的两个坑

1. `SeedRepository` 原先每次加载都 `deleteAllKnowledgePoints()` 整表清空。
   只有数学时看不出问题，一旦加入第二科，每加载一科就把前面所有科目删掉，
   最终库里只剩最后一科——表现为「只有数学有知识点」。
   现改为按科目替换（新增 `deleteKnowledgePointsOfSubject` /
   `deleteEdgesOfSubject`，后者用「端点属于该科目」的子查询界定）。
2. 阶段 D 的候选清单原先不分科目。知识点扩到 700+ 节点后，
   一道物理题的候选里会混进语文、英语的节点，模型很容易给出跨科目的错误归属，
   而错误归属会直接污染掌握度统计。
   现改为：阶段 A 识别出 `subject` 后，把候选收敛到同一科目；
   收敛失败（该科目没有节点）时退回全量，宁可候选嘈杂也不让阶段 D 白跑。

### 14.8 导出产物必须落到用户看得见的地方

原实现把 PDF 写进 `cacheDir/review_material/`，只在界面打一行文件名。
cacheDir 是应用私有临时目录：文件管理器看不见、进不去，系统清理时还会被删。
用户点了「导出」却什么都拿不到，等于功能不存在。

现改为三级策略（逐级降级，绝不静默失败）：
1. 写入系统「下载/ToTop」（`MediaStore.Downloads`，Android 10+，无需存储权限）；
2. Android 9 及以下写应用外部私有目录 + FileProvider；
3. 同时保留 `content://` Uri，界面提供「打开」「分享 / 打印」两个真实出口。

打印刻意**不直接接系统 PrintManager**：那需要自己实现 `PrintDocumentAdapter`
把 PDF 一页页渲染过去，各家 ROM 行为不一致。改用「分享给打印 App」这条路径，
打印服务 App 自己会处理 A4 排版，兼容性反而更好。

### 14.9 科目归一不再兜底到数学

原实现 `Subjects.codeOf` 识别不了就返回 `math`，
使「综合」「通用」这类题悄悄计入数学错题本——学生在数学错题本里看到一道物理题，
无法理解也无法纠正。

现新增 `Subjects.normalize`：支持「数学 / math / Math / 初中数学 / 高中数学」等写法，
识别不了时落到 `general`（显示为「通用」），不再污染数学统计。
同时新增「技术」科目（浙江省选考，信息技术 + 通用技术）。

### 14.10 日统计按科目拆分

`DailyStatsWorker` 原先把当天**全部**错题都记在 `subject = "math"` 这一行上。
一旦学生做了物理题，数学的日统计会凭空多出物理错题，学情报告里「按科目看」完全失真。
现改为：先写合计行（`subject = "all"`），再按 `countGroupBySubject` 的结果逐科写行。

已知限制：`daily_stats` 的 DAO 没有「按科目 + 日区间」的计数查询，
因此科目行的 `mistakeCount` 暂时保留已有值不动，
精确的科目维度统计由周报走 `mistake_record JOIN question` 实时查询给出。
这是刻意取舍：不为了一个次要指标去改表结构与写迁移。

### 14.11 框选归一化漏除画布尺寸（0.2.0 修复）

第一轮修复了 `pointerInput(Unit)` 的闭包捕获问题，但漏掉了另一处更隐蔽的缺陷：
`toNormalized` 把像素坐标直接 `coerce(0f, 1f)` 当作归一化坐标，**没有除以画布尺寸**。

后果：任何超过 1 像素的坐标都被夹成 1.0，于是 `left == right == 1.0`，
函数判定「宽高为 0」返回 null，调用方把 null 当作「用户取消框选」写回状态。
用户看到的就是「画完一松手，框立刻消失」。

现在：`toNormalized(rect, canvasWidth, canvasHeight)` 显式要求画布尺寸并做除法；
并且**误触不再等价于取消框选**——只有真的框到东西才回调，
「改用整张图」必须由用户点专门按钮表达。

### 14.12 提示词按科目硬编码（0.2.0 修复）

四个阶段提示词都写死了数学：阶段 A 的 `subject` 枚举只有 `"math"`，
阶段 B/C 的角色描述是「中学数学教师」/「数学评分标准」，
阶段 D 的 ID 正则写死 `^KP_MATH_[0-9]{4}$`。

这直接导致「一解非数学题就报错」：阶段 A 无论识别出什么科目都返回 `math`，
阶段 D 在非数学科目下拿到的候选 ID 无法通过正则，四阶段合并后契约校验失败。

现在：科目枚举扩到十科 + `general`，ID 正则改为 `^KP_[A-Z]{2,12}_[0-9]{4}$`，
阶段 B/C 明确要求按科目规范作答。`promptVersion` 同步升到 1.1.0，
旧缓存自动失效（缓存键含 promptVersion）。

### 14.13 KNOWN_SUBJECTS 漏了四个科目（0.2.0 修复）

`KnowledgeIdConvention.KNOWN_SUBJECTS` 只列了六科，
政治、历史、地理、技术的合法知识点 ID 会被 `isKnownSubject` 判为非法。
虽然映射器只校验 `isValid`（正则），但任何用到 `isKnownSubject` 的地方都会误判。
现补齐十科，与知识点树种子数据保持一致。

### 14.14 讲解模式合并为两档（0.2.0）

原三档 `DIRECT` / `GUIDED` / `SOCRATIC` 在真机上的实际差异很小：
GUIDED 会直接渲染整份标准步骤，观感与 DIRECT 几乎无差别；
SOCRATIC 又不给任何可操作的抓手，只堆问题。

现合并为两档，差别只落在「给不给最终解答」：

| 模式 | 步骤 | 答案 | 提示 | 引导提问 |
| --- | --- | --- | --- | --- |
| DIRECT | 全量 | 有 | 无 | 无 |
| GUIDED | 空（需主动揭示） | 无 | 三级 | 有 |

兼容性：`TeachingMode.fromWire("SOCRATIC")` 返回 `GUIDED`，
`fromWireOrNull` 同样返回 `GUIDED` 而非 null。
这样设置表与错题记录里的旧值不会导致模式重置或数据读不出来。

### 14.15 错题详情与复习分成两个入口（0.2.0）

原实现点一道错题直接跳复习页。学生想「看看我当时错在哪」时被迫进入做题流程，
两件事被混成一件。

现在：列表点卡片 → 只读的**回顾页**（原题 + 我当时写的 + 错因 + 标准解答 + 知识点）；
顶部「复习」按钮 → 原有的 SM-2 复习流程。

详情页独立于错题本的理由：它要一次 JOIN 取回 `question` 与 `mistake_record` 的完整快照
（含原图路径、学生步骤与标准解答两个 JSON 列），与列表的投影字段完全不同，
塞进同一个接口会让两边都出现大量用不上的字段。

## 15. 第四轮真机反馈中的取舍（0.3.0）

### 15.1 带图请求一律走视觉档

原方案 3.3 的分级路由只看 OCR 快照：印刷体 + 置信度 >= 0.80 + 无图形 → 文本档。
这在纸面拍题场景下是**错的**：题目条件、几何图、表格往往只在图上，
OCR 文本必然有损耗；更严重的是多页题目——第 2 页起根本不会进文本档的上下文。

现在 `ModelRouter.route` 增加 `hasImages` 入参，判定顺序变成：
**带图 → 视觉**（优先于手写/含图/低置信度）；不带图时才按原规则。

代价：所有拍题请求都会命中视觉模型（更贵）。
接受这个代价的理由是：文本档在这条链路上给不出可用结果，
省下的 token 换来的是「答非所问」，反而更浪费。

单测 `ModelRouterTest` 里的纯函数 `decideWith` 保留旧签名（`hasImages` 默认 false），
原有矩阵断言不受影响。

### 15.2 「完全不会」不再判为步骤缺失

固定七类错因里，`步骤缺失` 的语义是「写了过程但漏了关键一步」。
原提示词让模型对学生只说「不会」的情况也取该值，这在语义上是误诊：
学生连第一步都没开始，告诉他「你跳过了一步」既不对，也会把复习方向带偏
（错因统计会显示「步骤缺失」偏多，而真实短板是「不知道从哪切入」）。

现在：完全不会 → `方法选择不当`；只有「有过程但漏步」才用 `步骤缺失`。
提示词版本 1.1.0 → 1.1.1。

### 15.3 会话 ID 改为落盘时按需生成

会话持久化的成立前提是存在会话 ID，而原实现只读不写。
补一个「新建会话」按钮并不能解决——用户在任意一轮对话里都可能直接发送，
不一定经过那个按钮。

现在 `persistSession` 在 ID 为空时现场 `create()` 并写回状态。
副作用是首轮对话也会立刻出现在历史列表里，这正是用户预期。

### 15.4 陪伴作业：只做节奏，不做游戏化

新增的陪伴模式刻意**不做**以下事情：

| 不做 | 原因 |
| --- | --- |
| 排行榜 / 班级对比 | 本项目无自建后端，也不允许新增统计 SDK；本地排名没有意义 |
| 连续打卡 | 打卡会诱导「为了不断签而刷题」，与本项目「先把不会的搞懂」的口径冲突 |
| 强制锁屏 / 强制计时 | 陪伴模式的定位是「有人看着时间」，不是家长管控工具 |
| 到点推送通知 | 写作业时弹通知本身就是干扰 |

做的是：每题一个可选的倒计时（3/5/8/10 分钟，默认 5 分钟）、
时间到之前不给求助入口、到点后解锁「问一下 AI」并计一次求助、
一轮结束后给一份朴素的复盘（自己写完几题 / 求助几次 / 累计思考多久）。

### 15.5 设置页从「长列表 + 折叠」改为「目录 + 子页面」

原实现把所有设置塞进一个页面，且「模型与连接」默认展开，
每次进设置第一眼都是十几个输入框。折叠面板只是把问题推迟了一步：
用户仍然要先展开、再在展开的长表里找。

现在设置页只有四个条目，每个条目一行摘要（例如「已配置 / 未配置」），
点进去是独立子页面（`SETTINGS_MODEL` / `SETTINGS_TEACHING` / `SETTINGS_STORAGE` /
`SETTINGS_ABOUT`），可以正常返回。子页面共用 `SettingsSubScreen` 外壳，
返回位置与边距完全一致。


## 16. 第五轮真机反馈的取舍（0.3.1）

### 16.1 「追问」与「新题」的分界：只看这一轮有没有新图

原判定写成「会话里已有解答 **且** 输入区没有图片 → 追问」。
它看起来对，实际不成立：`runSolve` 结束后并不清空输入区的图片
（保留是为了让用户看清刚才拍的是哪道题），于是拍完题再打字时
`hasPages` 仍为真，条件不成立，落进解题分支——同一张图被重新解一遍，
学生感觉「我明明是在追问，它却按新题重做了」。

现在分界改成**这一轮是否明确附加了新图片**：
带新图 = 换题；不带图 = 问的是当前这道题。这个规则的好处是用户能自己总结出来，
不需要理解「输入区有没有残留图片」这种实现细节。

### 16.2 解题气泡必须连结构一起落盘

会话文件原来只存 `ChatTurn.text`（一句话正文）。重开历史会话时，
解题气泡退化成一条普通 AI 消息：卡片区块消失，追问也拿不到原题与原解——
这正是「重新打开旧对话后，打字追问它又从头解一遍」的来源。

补的办法不是把整套展示模型搬进 `data`（那会违反分层：data 不能依赖 ui），
而是在 `ChatTurn` 上加一个 `solutionJson: String?`：ui 层负责序列化与反序列化，
仓储只搬运一段不透明文本。序列化失败时降级为只存正文，历史仍然可读。

代价是会话文件变大（一道题的快照约几 KB）。接受的理由：会话是阅读记录，
体量可控（单会话几十条消息），而「结构丢失」是功能性缺陷，不是体积问题。

### 16.3 选项必须渲染，多选题要在提示词里兜住

「多选题只给一个选项」有两个独立成因，只修一个不会好：

| 层 | 问题 | 处理 |
| --- | --- | --- |
| 展示 | 阶段 A 解析出的 `options` 一路传到 `SolutionPayload` 却从未渲染 | 题目卡渲染选项列表 |
| 提示词 | 阶段 B 没有任何「多选要选全」的要求 | 要求写全选项并逐步判断每个选项 |

现在两者都补上，并在「题干带多选线索、但答案只有一个字母」时就地给一句提示，
让用户知道可以追问「其他选项为什么不对」。

### 16.4 小问：分段显示 + 提示从卡住的那一问起

大题按 (1)(2)(3) 分问，原来的实现把标准步骤平铺成 1..n，
一道三问的大题变成十六步连续推导，学生分不清「现在看的是哪一问」；
提示更是永远从第 1 问起——学生说「我不会第 (3) 问」，收到的却是「先配方」。

三处一起改：阶段 B 要求每步标注所属小问、阶段 C 要求把 `firstError` 指到卡住那一问的第一步、
客户端按小问切段（`StepSections`）并据此决定提示起点。

**已知取舍（本轮已解决）**：`firstError.stepIdx` 是**学生步骤**的序号，
而提示要按**标准步骤**切段，两者只在「同一问内步序大致对应」时成立。
学生跳步、把多步压成一行时，这个假设就破了：提示会从该小问的中间某步开始，
压缩幅度大时还会落到上一问（「切段按小问起点取整」只保证不精确，不保证不越界）。

现在改用契约解决：阶段 C 的输出增加 `firstError.subQuestion`（1 起，整题不分问时为 `null`），
客户端直接按问号找标准步骤的小问起点，不再把学生步序号当标准步骤位置使用。
只有 `subQuestion` 缺失时才退回按 `stepIdx` 推算（旧会话文件、模型给 `null`、
或标准步骤里根本没有该问），最差回到旧行为。提示词版本 1.2.0 → 1.3.0（输出字段变化，升 MINOR）。

**残留（本轮不动）**：`TeachingModeTrimmer.buildHints` 里仍有同样的「拿 stepIdx 当标准步骤下标」
的写法，它派生的是 `SolvedView.hints`；而界面实际使用的是 `SolutionMapper` + `HintBuilder`，
`SolveOutcome.view` 在主源码中没有读取方，所以不影响体验。一旦要把这套 HintLevel 接到界面上，
必须按同一规则改用 `subQuestion`，否则这个缺陷会重新长出来。

### 16.5 提示一次给到第 2 级，第 3 级才需要再点

三级提示并不等价：第 1 级只有方法名（「这道题的主线是配方法」），
学生看完往往还得再点一次；第 2 级才是「下一步做什么」，多数人卡住时真正需要的就是它。
逐级点等于逼他多点一次废话，这就是「提示总是分三次给」的观感来源。

现在第一次点直接给到第 2 级；只有 2 级提示的题一次给全；
第 3 级（展开顺序与具体式子）仍然要再点一次——那是接近答案的内容，
提前给会把「自己先想」这一步彻底跳过。

### 16.6 追问省 token 的三处裁剪

| 裁剪 | 值 | 理由 |
| --- | --- | --- |
| 历史轮数 | 最近 6 轮 | 足够覆盖「刚才说到哪」这类指代 |
| 单条历史字符 | 400 字 | 防止某个超长回答把预算吃光 |
| 解题气泡 | 整条不进历史 | 它的内容就是 context，进历史等于同一份解答付两次钱 |

完整题目与解法由 `contextOfSolution` 单独给一次，历史只承载「对话进行到哪」。

### 16.7 陪伴作业的求助为什么新开会话

在陪伴模式里点「问一下 AI」，那一刻用户并没有在解某一道题，
把当前陪伴页面的内容塞进拍题上下文只会让模型拿到一份错位的题干。
所以走 `SOLVE_NEW`：强制开一条干净对话，且**不恢复上一条会话**
（否则进去看到的是上一道题的解答，像没生效）。

用独立路由而不是给 `SOLVE` 加参数：`cleanNew` 是「进入这一页时的初始动作」，
用参数表达会让同一路由在重建时反复重新开局，把用户刚拍的题清掉。

### 16.8 本轮刻意没做的事

- **自动滚动到卡住的那一问**：分组显示已经能让学生自己对上，
  再加自动滚动会与「展开动画」抢焦点，先观察真机反馈。
- **历史会话的按小问折叠**：会话回顾场景以读为主，折叠反而增加一次点击。

### 16.9 仓库根目录的图片归档到 `Image/`

用户提供的图标原图原本散落在仓库根目录（`新图标.jpg`），
与其他构建产物混在一起容易被误删或被 `git clean` 清掉。
现在统一放进 `Image/`，原图入库留档，重新导出各档 mipmap 时不必再向用户要一次。

### 16.10 版本号补记

0.3.0 那一轮只写了 Changelog，没有改 `versionCode` / `versionName`，
导致打出来的包仍自称 0.2.0，出问题时无法从包体反查到对应改动。
本轮一并补上：`versionCode` 3、`versionName` 0.3.1。

## 17. 第六轮真机反馈的修复与取舍（0.4.0）

本轮十项反馈中，凡是需求本身有多种合理解法的，都记在
[待决策项-0.4.0.md](待决策项-0.4.0.md)，这里只写**已经落地的决定与理由**。

### 17.1 「新建对话后再提问，AI 没有任何输出」：注册表被永久封存

`LlmCallRegistry.cancelAll()` 除了取消在途 Call，还把注册表标记为「已取消」，
此后 `register()` 会把**新**Call 立刻 cancel 掉。而 `startNewSession()`、
`openSession()`、`stop()`、复习页关闭 AI 校验都会调用它——
于是新建对话后发出的请求在建立连接前就被自己取消，界面只剩一条空回复。

这不是偶发：只要点过一次「新对话」或「停止」，后面每一次请求都必然如此。
之所以表现为「可能没有输出」，是因为部分路径（`retry()`、`askAgain()`）恰好调了 `reset()`。

修复：

1. `cancelAll()` 只取消在途 Call，注册表继续可用；
2. 新增 `cancelAllAndSeal()`，只给 `onCleared()` 用（页面销毁后再接受新调用没有意义）；
3. `startNewSession()` 的状态清理改为**同步**执行，只把「归档落盘」留在协程里。
   旧实现整段在协程内，归档的挂起期间用户若已发出新问题，恢复后的
   `cancelAll()` + `solveJob?.cancel()` 会把新请求一并取消，是同一症状的第二个成因。

单测 `LlmClientMockWebServerTest.callRegistryCancels` 的断言随语义更新：
`cancelAll` 之后 `isSealed == false`，`cancelAllAndSeal` 之后才为 `true`。

### 17.2 题目改为视觉模型直读，移除本地 OCR 主链路

OCR 的损耗在纸面拍题场景里是结构性的：公式上下标、几何图、表格、手写批注
都会被转丢，而模型拿到一段有损文本后无法回到原图核对。现在：

- 拍题链路不再调用 `OcrRecognizer`（`runOcrIfNeeded` 整体删除），
  拍完确认只回到对话页，不做识别；
- `SolveRequest.ocr` 保留为「题目文本」通道：**有图时为空**，只有纯文字提问才填；
- 提示词阶段 A 改为「题目一律由你直接看图读出，不要期待识别文本」，
  多页明确为同一道题的不同页；版本 1.3.0 -> 1.4.0（输入语义变化，旧缓存随版本失效）。

顺带补上一个取消 OCR 后暴露的漏洞：没有图片时，输入框里的文字现在被当作**题干**
（原先当作解题思路，导致纯文字提问必然报「阶段 A 未识别出题干」）。

### 17.3 一次对话只对应一道题：补拍是补充，不是换题

16.1 定的分界是「这一轮有没有带新图」，它在「AI 没看清、学生补拍一张」的场景下判错：
补拍被当成新题从头再解，前半段的错因与解答全部作废。

现在分界只有一条：**当前会话里已经有解答 → 之后的一切输入都属于这道题**。
带图时走 `FollowUpGateway` 并把图片交给视觉模型，系统提示里明确
「这是对先前那道题的补充，不要当成新题重新讲一遍」。换题的唯一入口是新建对话。

配套改动：

- `FollowUpGateway.ask` 增加 `images` / `supplementNote`；带图时模型换成
  `effectiveVisionModel`（文本模型会把图片整包丢掉，等于补拍无效）；
- 追问补拍也记进 `lastFollowUp`，重试时连图一起重发（否则重试退化成无图追问）；
- 输入框占位文案按「是否已有解答」切换，避免学生不知道该写思路还是写追问。

### 17.4 框选缺陷：坐标按控件而不是图片换算，且上传/展示不是同一张图

两个独立成因，都会表现为「框选没生效，发的还是原图」：

1. **坐标错位**：预览用 `ContentScale.Fit`，控件里留有 letterbox；
   框选层铺满控件并拿**控件尺寸**归一化，归一化坐标与图片像素整体错位。
   现在由 `ImageFit.contentRect` 算出图片的实际绘制矩形，框选层按它换算
   （命中测试、夹取、归一化、回显全部统一到同一个矩形）。
2. **展示的不是上传的那张**：学生气泡与 `question.imagePath` 用的是整页原图路径，
   即使上传已经裁剪，用户抬头看到的还是整页。
   现在裁剪结果按内容哈希落盘为 `filesDir/images/<sha256>.jpg`，
   气泡、会话历史与错题本统一指向裁剪图；`imageSha256` 同步更新为裁剪图的哈希，
   保证按图去重仍然有效。

`ImageFit` 是纯函数，单测覆盖竖图/横图居中、同比铺满、非法尺寸与归一化换算。

### 17.5 不再渲染模型的思考过程

阶段 A/B/C/D 的流式增量是**结构化 JSON**，旧实现把它们直接拼进气泡，
学生看到的是几百行 `{"subject":"math"...}`，既读不懂也判断不了进度。

现在解题期间只显示「AI 正在思考… · 阶段名」（6dp 圆点做透明度呼吸），
完成后一次性换成结构化解答。追问的增量是**真回答**，仍然实时渲染。

### 17.6 「我已理解」按钮

位置在输入框正上方（不是消息流末尾：追问越多，末尾越难找）。
显示条件：已有结构化解答，且最后一条是**正常结束**的 AI 回复。
点击 = 新建对话（归档当前会话 + 清空输入区）。

「之后要不要联动掌握度 / 自动打开相机」属于产品口径，列入待决策项。

### 17.7 语音输入

用系统 `SpeechRecognizer`（`RecognizerIntent`，zh-CN，开启部分结果），
点一次开始、再点一次结束，识别文本实时回填输入框。

取舍理由：本项目 BYOK 直连厂商、不新增第三方 SDK；系统识别在国产 ROM 上由厂商引擎完成，
中文口语够用且免费。两条限制如实提示：本机没有识别引擎、以及部分机型需要联网。

新文件 `ml/VoiceInput.kt`（识别层），权限申请复用相机那套 Composable 形态，
`RECORD_AUDIO` 与 `RecognitionService` 查询此前已在清单里声明，本轮无需改清单。

### 17.8 启动动画

系统 splash 只保证冷启动第一帧不是黑屏，做不了动画；本轮补上应用内的一段：
图标 + 名称 + 一句话，420ms 内从 0.92 放大到 1.0 并淡入，最短展示 620ms，
之后 260ms 淡出露出首页。只动透明度与整体缩放，不做位移与循环动画。

「此前要求的启动动画」在仓库里没有文字依据，具体形态列入待决策项。

### 17.9 页面过渡：从「全部关闭」改为短促的淡入 + 微位移

13.6 当时把四条过渡全设为 `None`，原因是默认过渡（约 300ms）期间目标页在做数据库查询，
低端机上表现为「点了没反应然后突然跳过来」。完全关掉解决了卡顿，但也抹掉了层级关系：
进二级页与回退看起来一模一样。

现在取一个折中：进入 180ms、退出 120ms，位移只有屏宽的 1/18，
push 从右侧、pop 从左侧；不缩放、不做共享元素、不叠阴影动画。
每帧只有一次 alpha 与图层平移，比系统默认轻，且方向可辨。

### 17.10 输入区布局

旧版一行里挤了「拍照」「相册」两个带文字的竖排按钮 + 输入框 + 发送，
输入框实际可用宽度不到一半。现在：

- 拍照 / 相册收进输入框左侧的「+」菜单；
- 麦克风放进输入框内部右侧，语音状态用图标与一行提示表达；
- 发送/停止留在最外层。

可点元素从 5 个降到 3 个。「拍摄是否值得常驻」列入待决策项。

### 17.11 科目中文名只有一份映射

`ui/mistakes` 里的 `subjectLabelOf` 自带一张只覆盖六科的 `when` 表，
政治、历史、地理、技术与兜底科都被原样显示成英文代码——
错题本里的「技术」显示为 `technology` 就是这么来的。

现在直接委托 `Subjects.label`，只额外处理空值（「未标注学科」）。
单测 `SubjectLabelTest` 覆盖十科 + 兜底 + 大小写/空白 + 未知代码。

## 18. 0.5.0 第一批：输入区、语音、启动页与过渡（本轮）

口径见 `docs/需求定稿-0.5.0.md`，本节只记「为什么这么做」与「代价」。

### 18.1 相机回到常驻位

0.4.0 把拍照与相册一起收进输入框左侧的「+」，代价是每次拍题都要多点一次，
而拍题正是这个应用最高频的动作。本轮改回三段式：

    左键（语音/键盘）| 中区（输入框 或 按住说话）| 右侧（相机、更多）

「更多」里只放相册。一行里的可点元素仍是 5 个（含发送），但都落在拇指区，
且拍照回到一步可达。发送键在语音态下只在有内容时出现，避免空态占位。

### 18.2 语音改为按住说话

旧实现点一次开、再点一次关：需要一手点一手说，且引擎与用户对「说完了」的判断不一致。
现在按下即录、松手结束、上滑 24dp 锁定（松手继续录，再点一下结束），
录音时用 12 根声纹条表达音量。

三个实现细节值得记：

- 手势用 `awaitEachGesture` 手写，不用 `detectDragGesturesAfterLongPress`——
  后者要等长按判定（约 500ms）结束才回调，第一个字会被吃掉；
- 锁定会触发重组，重组会取消正在跑的 `pointerInput` 协程，
  因此协程里所有回调都走 `rememberUpdatedState`，否则拿到的还是第一帧那份 lambda；
- 首次授权时系统弹框会打断手势，授权回来时手指早已松开，
  用 `pressHeld` 标记区分「还按着」与「弹框回来」，避免录到 55 秒上限。

### 18.3 识别引擎可选、离线自动回退

国产 ROM 自带的识别服务中文口语明显好于系统默认，但个别机型自带引擎必须联网，
没有统一的「谁更准」，所以把选择权给用户：

- 设置 → 教学偏好 → 语音识别：枚举 `queryIntentServices(ACTION_RECOGNIZE_SPEECH)`，
  API 31 及以上额外提供「本机识别（离线）」；
- 默认选非 Google 的厂商引擎；选择存 SharedPreferences（`data/prefs/VoiceEnginePrefs`），
  不进 Room——它不参与统计、不进导出、不需要迁移；
- 识别时按网络状态传 `EXTRA_PREFER_OFFLINE`；`ERROR_NETWORK` 时自动换离线引擎重试一次并告知用户；
- 同一引擎连续两次空结果提示换一个，进程内只提示一次；
- 单轮 55 秒上限；松手后 4 秒兜底收尾——部分国产引擎不回调 `onResults`，
  没有兜底界面会一直停在「正在整理」。

### 18.4 启动过程只剩一种淡紫

窗口底色从 `#F4F1FC` 改为 `#EFEAFB`，与启动页的 `Tokens.Splash` 逐位一致，
Android 12+ 的 `windowSplashScreenBackground` 也指同一色。低端机冷启动那 2 至 3 秒
看到的就是这层底色，不再是黑屏；随后字标五个字母逐个淡入（每字 70ms、各上移 8dp），
定格后淡出进首页，最短展示 700ms。

导航栏改为 `@color/status_bar`：底色变紫后若导航栏继续跟随，会得到一条紫边。
启动页不再显示图标与副标题，只留字标——需求只要求「字样逐个出现」。

### 18.5 过渡动画「完全看不到」的三层原因

真机反馈是「完全看不到过渡动画」，排查后是三层叠加，任何一层单独修都不够：

1. 位移只有屏宽 1/18（约 20dp），而两页背景同为白色，淡入淡出在视觉上没有参照物；
2. 系统动画缩放设为 0.5 时，Compose 会把 180ms 再砍一半，只剩 90ms；
3. 目标页首帧还在查库，动画在空白期就跑完了。

处理：进入 260ms + 屏宽 1/10 位移 + 0.985 推近，退出 200ms；
底栏同级切换只淡入不做横移（并列关系不该有方向感）；
时长按系统缩放反向补偿、下限 0.8——系统把动画彻底关掉时不补偿，那是无障碍选择。

### 18.6 本轮没做

「已掌握」勾选、补拍更新错题、错题本多页免框选、陪伴改造与入底栏属于 P1；
功能中心宫格、引导里的 API 教程、首页文案与鼓励语属于 P2。
启动页与过渡的实际观感需要 K30 真机确认，本环境没有设备，只验证到编译、ktlint、detekt 与单测。

## 19. 0.5.0 第二批：已掌握与多页错题（本轮）

数据库因此升到 v2（`MIGRATION_1_2` 加两列），schema 快照与迁移用例一起补。

### 19.1 「我已理解」改成顶栏勾选「已掌握」

旧实现是输入框上方的一条横幅，点一下等于「新建对话」——名字叫理解，做的事是清空。
现在改成顶栏勾选图标（在「+」左边），点一下做三件事：写 `question.selfMasteredAt`、
归档当前会话、开一条干净的新对话，并给一句收束语。

为什么只写一个字段、不动 `mastery` 表：掌握度由复习自评、错题频次、覆盖度加权算出，
学生点一下就把分数抬起来会污染推荐路径与周报（口径见 `docs/需求定稿-0.5.0.md`）。
所以这个标记的语义只有一句：**这道题我确认会了**。

按钮在「本题答完」（已有结构化解答且最后一条 AI 回复正常结束）之前置灰，
避免学生在还没看到解答时就把题标掉。

### 19.2 错题本保留全部页、不提供重新框选

`question` 新增 `imagePathsJson`（全页列表，顺序即页序）；`imagePath` 仍是第 1 页，
继续承担缓存与去重的锚点。详情页用 `HorizontalPager` 横向翻页，右上角显示「2 / 3」。

读取侧对旧记录做了兜底：`imagePathsJson` 为空数组时回退到 `imagePath`，
不回填数据——旧记录只有一张图，回填也变不出第 2 页。

详情页**不提供**重新框选入口：图是拍题阶段裁剪后的成品，在这一页再框一次会得到一张
和题目对不上的新图，破坏错题与图片的一一对应；要重框就回拍题页重拍。

### 19.3 迁移与测试

- `MIGRATION_1_2`：两条 `ALTER TABLE question ADD COLUMN`，都带默认值，旧记录不动；
- `app/schemas/.../2.json` 随构建导出并入库；
- `MigrationTest.migrate1To2KeepsOldRows`：v1 写一条记录 → 迁移到 v2 → 断言旧记录还在、
  `selfMasteredAt` 为 null、`imagePathsJson` 为 `[]`。

### 19.4 还没做的两项

- **补拍更新错题**：`AiGateway` 是一条把 A→B→C→D 串起来的 channelFlow，没有「只跑 A」的入口。
  要做对，得先抽出一个只识别题目的调用与提示词，再解决「同一条错题被改两次」的去重与复发计数。
  半做（只更新图片、不更新题干与知识点）会让错题本显示一张新图配一段旧题干，比现在更糟，因此留到下一轮。
- **陪伴作业改造**：需要新表（易忘点、专注时长）、一个轻量问答网关与提示词、底栏加到四项，
  一轮做不完；页面目前仍是「五分钟倒计时」，与新口径相反，下一轮优先替换。

## 20. 0.5.0 第三批：陪伴作业改造（本轮）

上一版的陪伴是「每题五分钟倒计时，到点前不给求助按钮」，与「写作业时随时问」直接冲突。
本轮把它整个换掉：正计时 + 页面内随手问 + 进底栏。

### 20.1 倒计时改为正计时

- 计时只回答「这一轮写了多久」，不设截止时间，不再有「时间到」这个状态；
- 本题 5 分钟时给一条提醒「这题已经 5 分钟了，卡住可以问我」，每题只提醒一次，**不打断计时**；
- 「写完了」把本题用时并入本轮累计，重新开始下一题；
- 本轮结束的复盘从「求助几次」改成「写完几题 / 专注多久 / 问过几次」。

原来每题的时长选择（3/5/8/10 分钟）随之删除：正计时下「每题给自己多少时间」这个设置没有意义。
`settings` 表里的 `companionPerQuestionSeconds` 因此成为历史键，读取处已移除，不做迁移——
它只是本地偏好，留着也不影响任何统计。

### 20.2 随手问：页内单轮，不跳拍题

上一版的求助是跳到拍题页重开一条对话，等于把「写作业」打断成「做题」。
现在提问框常驻在计时下面，文字或按住说话都行，走一条**独立的单轮链路**：

- 提示词外置在 `assets/prompts/companion_ask.md`，明确要求「只讲被问的那个点、不给作业答案、200 字以内」；
- 不复用 `FollowUpGateway`：追问的上下文是「某一套标准解答」，而陪伴模式根本没有题，
  硬套会让模型围绕一份不存在的解答作答；
- 不落库、不缓存：一句话的提醒，重复问时重新生成更自然；
- 提问时计时暂停，回答完自动恢复；如果提问前本来就暂停着，回答完仍保持暂停。

这条提示词不参与缓存键，因此没有升级 `prompt_version.json`——它是新增文件，
不属于「修改既有阶段提示词」。

### 20.3 底栏加到四项

首页 / 拍题 / 陪伴 / 功能中心，四项等宽同级。陪伴用计时器图标，标题从「陪伴作业」缩到「陪伴」。
胶囊左右留白从 20dp 收到 14dp、图标 19dp 到 18dp、图标与文字间距 5dp 到 4dp，
否则四项在 360dp 窄屏上会挤成一排小字。

首页与功能中心里的陪伴入口改为顶层跳转（`navigateTopLevel`），
否则会在底栏页之上再叠一层同样的页面，返回时要按两次。

### 20.4 还没做的部分

- **易忘点落库与联动**：问过哪些知识点、要写进「需要多练」、要并入复习资料，
  这部分需要新表 + 知识点匹配 + 首页/复习资料的展示改造，本轮没做；
- **专注时长写进学情报告**：目前只在页面内统计并展示，尚未按天落库。

这两条是「陪伴作业」的下一半，接在易忘点表一起做，避免先落一半数据再改表。

## 21. 0.5.0 第四批：易忘点与专注时长（本轮）

数据库升到 v3（只加一张表），首页与复习资料同时接上。

### 21.1 为什么单独建 forgotten_kpoint

陪伴模式里的提问是「写作业时忽然想不起来」，没有错题、没有学生步骤、没有错因。
硬挂到 `mistake_record` 上会污染错题统计、复发计数与掌握度公式，因此单列一张表：
一行一个知识点（主键 kpointId），重复提问只累加 `askCount` 并刷新 `lastAskedAt`，
表的大小上限就是内置知识点数量。

### 21.2 知识点匹配用名字子串，不额外调用模型

问句通常就是「链式法则是什么」这种短句，直接拿内置目录的知识点名去比对即可：
命中名字长度 >= 3 的才算（避免「函数」「方程」这类过短词把整页点都命中），
一句话最多记 3 个。这样不增加 token、离线也能用；代价是名字没被说出口时记不上——
可接受，漏记只是少一条提示，误记才会污染「需要多练」。

### 21.3 专注时长复用 daily_stats，不新建表

`daily_stats.studySeconds` 本来就是「学习时长」，周报的「学习时长」与「活跃天数」
都从这张表聚合。陪伴的专注时长按天累加进去，学科用保留键 `_focus`：

- 报告不必改一行代码就统计得到，也不用同时维护两个「时长」口径；
- 保留键以下划线开头，不会被当成真实科目展示；
- 代价是「专注时长」无法与「做题时长」分开看——真要分开，得给 daily_stats 加一列，
  那是下一次表结构变更该做的事，现在加只是为一个还没人问过的细分。

### 21.4 首页并列展示

首页在「还需要多练的知识点」上方新增「写作业时常问的」，最多 3 条，按提问次数排序。
两者分开列而不是合并：一个是做错的、一个是想不起来的，成因不同，
合并后学生看不出该补的是「练」还是「记」。

### 21.5 复习资料纳入

生成复习资料时把本科目的易忘点（最多 6 条名字）作为额外段落放进用户消息，
并在提示词里要求「优先把其中与本科目相关的写进 weakKpoints」。
只给名字不给次数：次数对学生没有意义，还会挤占上下文。
这条提示词在 `ReviewMaterialGateway` 内部拼装，改动不影响四阶段提示词版本号。

### 21.6 仍未做

「补拍后更新错题」仍是 P1 的最后一件事，卡点没变：`AiGateway` 没有「只跑阶段 A」的入口，
需要先抽出识别题目的单次调用与提示词，再处理同一条错题被改两次的去重与复发计数。

## 22. 0.5.0 第五批：补拍后更新错题（本轮）

P1 的最后一项。之前一直没做，是因为 `AiGateway` 是一条把 A→B→C→D 串起来的
`channelFlow`，没有「只跑阶段 A」的入口；半做（只换图不换题干）会让错题本出现
「新图配旧题干」，比不改更糟。

### 22.1 新增 IdentifyOutcome 与 identifyOnly

`AiGateway.identifyOnly()` 复用同一套路由、提示词装配与 `callStage`，
只跑阶段 A 并解析出 `AiQuestion`，不写缓存（补拍图是新的 sha256，缓存里本来也没有）。

### 22.2 为什么只跑 A，不重跑 B/C/D

补拍是「同一道题的补充照片」，不是换题：

- 解答（B）、错因（C）在第一次识题时已经定下，重跑 B 会得到一份**新的**解答，
  与已有的错因、提示解锁记录、复发计数全部对不上；
- 需要修正的只有「原题到底写了什么」这一件事；
- 知识点（D）同理不重算：题干变化到需要换知识点，说明这已经是另一道题，
  正确做法是新开一条对话，而不是悄悄把旧错题改归到另一个知识点下。

### 22.3 更新范围

`QuestionRepository.updateRecognized()` 只改五项：题干、已知、所求、选项、是否含图，
外加图片列表。以下字段**不动**：

| 字段 | 为什么不动 |
| --- | --- |
| `imageSha256` | 它是缓存与去重的锚点，跟着补拍图改会让同一道题变成两条记录 |
| `subject` / `createdAt` | 补拍不改变题目归属与入库时间 |
| `mistake_record` / `mistake_kpoint` | 解答与错因仍然成立，改它们等于重判这道题 |

图片按「旧页在前、补拍页追加」合并去重，最多 6 页：再多也不会有人一页页翻。

### 22.4 失败只提示，不改数据

阶段 A 调用失败（模型未配置、网络、输出解析失败）时只弹一句
「照片已用于本次回答，错题本未更新：原因」，保留旧题干。
写入一份没校验过的识别结果，比留着旧题干危险得多。

### 22.5 代价

补拍会多一次阶段 A 的调用（约 1.5K 到 3K token）。这是「题干正确」的必要成本：
补拍本来就是学生发现「AI 看错了」之后的补救动作，如果补救只影响当轮对话，
错题本里仍然是错的，这个动作就白做了。
