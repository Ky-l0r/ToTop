# 低端机测试清单

依据《AI 辅助学习 App 开发方案》7.1 至 7.3 节建立。
所有条目必须在真机验证，**禁止仅用模拟器判定**。模拟器无法反映真实的内存压力、
温控降频与 WebView 表现，用模拟器得出的结论一律视为无效。

本清单在 M8 性能优化阶段执行并填写实测数据，早期里程碑用于回归防劣化。

## 三、实测方法

### 3.1 环境准备

- 关闭开发者选项中的动画缩放（三处均设为关闭），避免动画干扰帧率测量
- 每台机器测试前重启，排除其他应用干扰
- 记录测试时的电量与温度，低电量或高温降频会显著影响结果

### 3.2 关键命令

| 目的 | 命令 |
| --- | --- |
| 冷启动耗时 | `adb shell am start -W -n com.totop.app/.MainActivity` |
| 帧率统计 | `adb shell dumpsys gfxinfo com.totop.app` |
| 内存占用 | `adb shell dumpsys meminfo com.totop.app` |
| 模拟低内存回收 | `adb shell am kill com.totop.app` |
| 查看 GPU 过度绘制 | 开发者选项打开「调试 GPU 过度绘制」 |
| 查看布局层级 | 开发者选项打开「显示布局边界」 |

### 3.3 远程调试

公式渲染与图谱页面用 Chrome DevTools 远程连接真机页面检查：
打开 `chrome://inspect`，选中设备的 WebView 页面，观察渲染耗时与内存。
**不接受仅在桌面浏览器中验证的结果**，移动端 WebView 行为差异明显。

## 四、记录要求

每次实测在 `docs/eval/` 下留存一份结果文件，命名 `performance-YYYYMMDD-机型.md`，
必须包含：

1. 机型、系统版本、内存大小、测试时的电量与温度
2. 每个检查项的实测值与是否达标
3. 未达标项的**原因分析**与后续处理，禁止留空或只写「待优化」
4. 若某项因硬件限制无法测试，写明原因并给出替代验证方式

连续两个版本未复测的项目，在下次发布前必须补齐，避免性能悄悄劣化。

## 五、常见问题排查

| 现象 | 可能原因 | 排查方向 |
| --- | --- | --- |
| 首屏超过 2 秒 | 数据库初始化阻塞主线程 | 把建表与种子装载放到后台线程 |
| 列表滚动掉帧 | 图片未用缩略图、单次查询过多 | 改用分页与缩略图 |
| 内存持续增长 | Bitmap 未回收、WebView 未销毁 | 检查图片缓存上限与页面销毁逻辑 |
| 公式渲染慢 | 每题新建 WebView | 复用 WebView 实例 |
| 后台返回白屏 | 状态未保存 | 用状态流保存页面状态 |
| 断网后一直转圈 | 未设置请求超时与错误回调 | 检查超时与错误映射 |
