# AI 分析链路设计

目标：把「一次考试的题目 + 学生实际作答」变成结构化的**失分知识点清单**和**可执行的提升指南**。

## 1. 输入与预处理

```
题目来源                          答题卡来源
├─ 拍照 → JPEG                     ├─ 拍照 → JPEG
├─ PDF  → PyMuPDF 逐页转 PNG       ├─ PDF / 图片
└─ Word → python-docx 提文本        └─ 标记 is_graded（老师是否已批改）
                │                                │
                └────────────┬───────────────────┘
                             ▼
                    预处理流水线（服务端）
        ① 长边压缩到 1600px（质量 82）——直接决定模型 token 成本
        ② EXIF 旋转校正、灰度化增强对比度（拍歪/偏暗的答题卡）
        ③ 校验：模糊度过高（拉普拉斯方差 < 阈值）直接返回「请重新拍摄」
        ④ 题目文本优先用 PDF/Word 解析出的文字，比视觉识别更准更便宜
```

## 2. 两阶段调用（省钱且更准）

| 阶段 | 输入 | 输出 | 说明 |
| --- | --- | --- | --- |
| 阶段 A：题目结构化 | 题目图片/文本 | 每题的题号、题干、考点、分值、标准答案 | 一份试卷只跑一次，结果缓存到 `papers.ocr_text`，**同一试卷的多次分析复用**，是最大的成本节省点 |
| 阶段 B：失分归因 | 阶段 A 的结果 + 答题卡图片 + 是否已批改 | 结构化分析结果（见下） | 每次分析跑一次 |

若用户只上传了题目图片且没有答题卡，则只跑阶段 A。

## 3. Prompt 设计

### System

```
你是一位资深的中学学科教研员，擅长依据学生的真实作答做失分归因。
你的任务不是简单地指出"错了"，而是判断：
1) 这道题背后考的是哪个知识点；2) 学生失分的真实原因（概念不清/方法选择错误/计算失误/审题偏差/表达不完整/时间不足）；
3) 这个知识点在学科知识体系里属于哪个模块与章节；4) 给出可执行、可验证的提升动作。

要求：
- 只依据图片与题目文本中能看到的事实判断，不要臆造学生没有写过的东西。
- 如果某处字迹或批改痕迹看不清，把该项的 confidence 标为 "low"，不要猜测。
- 输出必须是严格合法的 JSON，不要输出任何解释性文字、不要使用 Markdown 代码块包裹。
- 所有文本使用简体中文。
```

### User（模板，`{{}}` 为变量）

```
【考试信息】{{exam_name}} | {{exam_date}} | {{grade}} | 是否已批改：{{is_graded}}

【题目与标准答案】
{{papers_text}}          ← 阶段 A 输出的结构化题干，含每题考点与分值

【学生作答】
（见随附的答题卡图片 {{image_count}} 张；已批改的答题卡上老师标注的勾叉与扣分即为判分依据）

【请输出以下 JSON】
{{output_schema}}
```

## 4. 调用参数（Qwen-VL / 百炼兼容模式）

| 参数 | 取值 | 理由 |
| --- | --- | --- |
| endpoint | `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions` | OpenAI 兼容协议，便于将来切换模型 |
| model | `qwen-vl-max`（识别质量优先）/ `qwen3-vl` | 试卷手写体与表格版面识别更稳 |
| messages | system + user（图片以 base64 data URL 放在 user 的 content 数组） | 多模态标准传法 |
| `response_format` | `{"type": "json_object"}` | 强约束输出为 JSON |
| `temperature` | `0.2` | 归因需要稳定，不需要创造性 |
| `max_tokens` | `4096` | 一份试卷 + 8~15 个失分点的充分余量 |
| 超时 / 重试 | 120s / 3 次指数退避（1s、2s、4s） | 视觉推理偶发超时 |

**降级策略**（按顺序）：

1. 首次调用失败 → 重试（退避）
2. 仍失败且图片数量 > 3 → 分批（按科目拆分）后合并结果
3. 仍失败 → `analysis.status = failed` + 错误文案，**退还点数**并写 `refund` 流水
4. 模型返回的 JSON 不合法 → 追加一条「上次输出不是合法 JSON，请只输出 JSON」的修正指令重试一次

## 5. 结果后处理

1. **Schema 校验**：Pydantic 校验失败即视为模型失败（不落库半成品）
2. **归一化**：`module` / `chapter` 与 `knowledge_modules` 字典做模糊匹配，统一命名，便于后续按模块统计
3. **落库**：`analyses.result`（JSON）、`model_name`、`prompt_tokens`、`completion_tokens`
4. **回写**：各科得分率写入 `answer_sheets.score`，让趋势接口能直接用
5. **低置信度标记**：`confidence = low` 的失分点在结果页显示「待确认」，不参与"最需要补的 3 个知识点"排序

## 6. 成本控制（决定这个产品是否亏本）

单次分析的模型成本 ≈ 输入图片 token + 文本 token + 输出 token。控制手段按收益排序：

| 手段 | 效果 |
| --- | --- |
| **题目结构化结果缓存复用**（同一试卷只识别一次） | 省掉最大的一块输入：整卷图片 |
| 图片长边压到 1600px、质量 82 | 图片 token 大幅下降，肉眼仍可辨识手写 |
| 限制单次答题卡页数（建议 ≤ 6 页） | 直接线性控制输入规模 |
| 题目用 PDF/Word 文本而非图片 | 文本 token 远低于图片 token |
| 按科目分批调用小模型，只在必要时用 `qwen-vl-max` | 允许按重要性分档 |
| 记录每次调用的 token 数 | 没有度量就无法优化，`analyses` 表已存字段 |

> 定价参考：阿里云百炼按输入/输出 token 计费，且 Qwen-VL 系列按图片分辨率档位计价，**具体单价请以百炼控制台当前价目为准**，不要用本文档中的任何数字做财务决策。上线前用 20 份真实试卷跑一遍，算出「单次分析平均成本」，再确认 1 点数（¥1.00 / iOS ¥1.50）能否覆盖。

## 7. 效果保障

| 问题 | 对策 |
| --- | --- |
| 拍照模糊、卷面歪斜 | 上传前做清晰度检测并拒绝；页面给出「平铺、正面、光线充足」的拍摄引导 |
| 手写体识别错 | 提示用户优先上传**老师已批改**的答题卡（勾叉与分数比手写答案更易识别）；结果页允许用户手动纠正失分分值 |
| 题目与答题卡对不上 | 导入时按学科配对；未配对时在结果页提示「该科缺少题目，仅依据答题卡判分」 |
| 幻觉（编造题目内容） | Prompt 明确禁止臆造；`confidence` 字段 + 前端展示「待确认」；evidence 必须引用原文片段 |
| 主观题无法判分 | 未批改模式下方言明"主观题存在误差"；作文类只做维度点评不给绝对分数 |
