# 构建与验证清单

本文件记录 To Top 的构建环境要求、实测数据与失败修复记录。
所有数据来自本机真实执行，未执行的项目明确标注为「未验证」，不写推测值。

## 一、环境要求

| 项目 | 要求 | 本机实际 |
| --- | --- | --- |
| JDK | 17 或以上 | Microsoft OpenJDK 21.0.3 |
| Android SDK | platform 34、build-tools 34.0.0、platform-tools、cmdline-tools latest | 由 `local.properties` 的 `sdk.dir` 指定 |
| Gradle | 8.7（由 wrapper 固定） | 8.7，通过 GRADLE_USER_HOME 重定向缓存 |
| Gradle 缓存 | 不写入 C 盘用户目录 | 通过环境变量重定向到非系统盘 |
| AGP | 8.5.2 | 见 gradle/libs.versions.toml |
| Kotlin | 1.9.25 | KSP 1.9.25-1.0.20，Compose 编译器 1.5.15 |

环境变量的推荐写法（Windows PowerShell）：

    $env:JAVA_HOME        = "C:\Program Files\Java\jdk-17"
    $env:ANDROID_HOME     = "C:\Android\Sdk"
    $env:ANDROID_SDK_ROOT = "C:\Android\Sdk"
    $env:GRADLE_USER_HOME = "C:\GradleHome"

## 二、他人克隆后的配置步骤

1. 安装 JDK 17 或以上，确认 `java -version` 可用。
2. 安装 Android SDK（推荐 Android Studio 的 SDK Manager），确保存在
   `platforms;android-34` 与 `build-tools;34.0.0`。
3. 在仓库根目录复制配置模板：

       cp local.properties.example local.properties

4. 编辑 `local.properties`，把 `sdk.dir` 改为本机 SDK 路径。
   Windows 路径需要转义反斜杠，或直接使用正斜杠：

       # Windows（反斜杠需转义）
       sdk.dir=D\:\\Android\\Sdk
       # 或直接使用正斜杠
       sdk.dir=D:/Android/Sdk

   `local.properties` 已在 `.gitignore` 中排除，**绝不要提交**。
5. 可选：设置 `GRADLE_USER_HOME` 把缓存放到非系统盘，避免占满 C 盘。
6. 执行 `./gradlew :app:assembleDebug` 验证环境。

若下载依赖缓慢，`settings.gradle.kts` 已配置阿里云镜像作为兜底，
官方仓库仍然优先。

## 四、失败与修复记录

按发生顺序记录，便于复现与避免重蹈。

### 4.1 Kotlin 1.9.24 编译器内部错误

现象：`compileDebugKotlin` 抛出

    org.jetbrains.kotlin.codegen.CompilationException:
    Back-end (JVM) Internal error: Couldn't transform method node ...
    Caused by: java.lang.NullPointerException
        at ...FixStackAnalyzer$InternalAnalyzer.executeAfterInlineCallMarker

触发代码位于 `LlmClient` 的「挂起函数 + channelFlow + 内联 lambda + 循环跳出」组合。

处理：Kotlin 升到 1.9.25，KSP 同步 1.9.25-1.0.20，Compose 编译器 1.5.15。
结论：1.9.24 后端缺陷，1.9.25 已修复；1.9.x 补丁线内 API 一致。**禁止回退。**

### 4.2 Kotlin 编译守护进程无法连接

现象：`Could not connect to Kotlin compile daemon`，构建自动回退到进程内编译并成功。

处理：在 `gradle.properties` 固定 `kotlin.compiler.execution.strategy=in-process`，
使受限环境与 CI 沙箱也能稳定构建。代价是失去增量编译守护进程，可接受。

### 4.3 KSP 缓存损坏

现象：`java.nio.file.NoSuchFileException: app/build/kspCaches/debug/backups/java`
或 `generated/ksp/debug/java/byRounds/1/..._GeneratedInjector.java`。

原因：**多个进程并行构建同一个工程**，互相删除对方的中间产物。

处理：清理 `app/build` 后重建。**收口与日常验证必须串行执行**，
并行开发时各自使用独立副本目录。

### 4.4 ktlint 误报 Composable 命名

现象：`ToTopTheme`、`SolveScreen` 等全部被 `standard:function-naming` 报错。

原因：Compose 官方约定 @Composable 函数用 PascalCase，与 Kotlin 普通函数的小驼峰规则不同。

处理：在 `.editorconfig` 加入

    ktlint_function_naming_ignore_when_annotated_with = Composable, Preview

这是 ktlint 官方为该场景提供的属性，不是关闭规则。

### 4.5 detekt 配置项归属错误

现象：`Property 'complexity>ThrowsCount' is misspelled or does not exist`、
`Property 'exceptions>ThrowsCount'`、`Property 'test-patterns'` 等。

原因：detekt 1.23.6 中 `ThrowsCount` 属于 `style` 规则集；
`LoopWithTooManyJumpStatements` 同样属于 `style`；
`test-patterns` 与 `style>OutdatedDocumentation` 在该版本不存在。

处理：逐条按报错把规则移到正确规则集，删除不存在的属性。
detekt 的报错信息会直接给出正确路径，按提示改即可。

### 4.6 Hilt + WorkManager 初始化冲突（已修复）

现象：应用启动后运行后台任务时崩溃，提示 Worker 无法实例化。

原因：`App` 实现了 `Configuration.Provider` 并提供 `HiltWorkerFactory`，
但没有关闭 androidx.startup 的 WorkManager 自动初始化，
导致 WorkManager 先用默认配置建实例，Hilt 注入不生效。

处理：在 `AndroidManifest.xml` 中用 `tools:node="remove"` 移除
`androidx.work.WorkManagerInitializer` 的自动初始化。

### 4.7 依赖缺口

成员报告过的缺口已补齐，均在 `gradle/libs.versions.toml` 中：

- `androidx.hilt:hilt-work` 与 `androidx.hilt:hilt-compiler`（`@HiltWorker` 必需）
- `androidx.room:room-testing` 的 `androidTestImplementation`（MigrationTestHelper 必需）
- `androidx.test:core` 独立版本键（不能复用 ext.junit 的版本）

## 六、注意事项

1. **构建必须串行**：多个 Gradle 进程同时构建同一工程会破坏 KSP 缓存（见 4.3）。
2. **不要回退 Kotlin**：1.9.24 无法编译本项目（见 4.1）。
3. **不要删除 in-process 编译配置**：删除后在受限环境会反复失败（见 4.2）。
4. **local.properties 永不提交**：签名材料同理，只走 CI Secrets。
5. **release 体积门禁**：CI 在 `release.yml` 中校验不超过 30MB，超限直接失败。
6. **真机性能另测**：本文件只覆盖构建与静态检查，低端机性能见
   [docs/低端机测试清单.md](低端机测试清单.md)。
