## 三、② 科目多选（P0）

### 口径

- 首次启动（引导之后）进入「你学哪几科」：**十科多选，不限数量、可全选**，至少选 1 科。
- **`general` 不是一门课，是「模型没认出科目」的标记，界面文案改为「未知」**。
  它不出现在多选列表里、不出现在科目页签里、也不参与任何科目统计；
  但带 `general` 的题仍然会出现在「全部」列表里——学生要知道有这么一道题，
  只是它没有归属，不进掌握度分母。
- 「通用技术」是真实科目，属于 `technology`（技术 = 信息技术 + 通用技术）。
  所以**绝不把 `general` 映射成 `technology`**：那会把认不出的题算成技术题，
  既污染技术的掌握度，又掩盖了模型识别失败这件事。

### 实现

1. 新键 `SettingsRepository.Keys.SUBJECTS`（逗号分隔代码串）、`SUBJECTS_PICKED`（是否选过）。
2. 纯逻辑收在 `domain/model/SubjectScope`：`parse/format/isVisible`，空值回落全选。
   **规则只有这一份**，界面与统计都调它，禁止各页自己判空。
3. `data/prefs/SubjectPrefs`：读写口，不重复规则。
4. 新页 `ui/onboarding/SubjectPickerScreen`，两个入口共用：
   - 首次启动（无返回键，选完去首页）；
   - 设置 → 学习 → 学习的科目（带返回）。
   `StartViewModel` 分三支：没看引导 → 引导；看过但没选过科目 → 选科目；否则首页。
5. 应用范围：`SubjectTabs` 只渲染已勾选科目；`MistakesViewModel` 的科目下拉与已选值收敛；
   `KnowledgeViewModel` 的科目分组过滤。
6. 首页统计与报告的**分母暂不调整**（它们按全表算），列在 0.6.1 再处理——
   因为改分母要连带改报告文案，属于另一件需要口径的事。

### 验收

- 只勾化学时，易错题与知识点的科目页签只有化学；取消勾选后再进，列表不再出现该科。
- 全选时与升级前一致（回归基准）。
- 带 `general` 的老记录：在「全部」里可见，科目下拉里没有它，显示为「未知」。

## 四、④ 易错题（P0）

### 口径

四个状态，默认「全部」：

| 状态 | 含义 | 从哪来 |
| --- | --- | --- |
| 不会做 | 拍了但没写过程、或明确说不会 | 拍题时勾「不会做」/ 阶段 C 判定无学生过程 |
| 待核对 | 学生自己做了，答案待确认 | 核对答案模式（⑨）产出的记录 |
| 做错 | 有学生过程且定位到首个错误步骤 | 现有 `mistake_record` |
| 已过关 | 变式连对达到阈值（⑩） | 刷题结果回写 |

### 实现

1. `mistake_record` 加 `status TEXT NOT NULL DEFAULT 'wrong'`、`source TEXT NOT NULL DEFAULT 'solve'`；
   `errorType` 允许空（不会做/待核对的题没有错因）。
2. DB 升 v4，迁移：`ALTER TABLE ... ADD COLUMN` + 历史记录 `status='wrong'`。
3. `MistakesScreen` 顶部加状态分段（全部/不会做/待核对/做错/已过关），行内徽标复用 `RecurrenceBadge` 的位置。
4. 文案统一改「易错题」：`strings.xml`、导航标题、首页卡片、报告；**路由 id 保持 `mistakes`**
   （改 id 要动 deep link 与全部跳转，收益为零），在偏离记录里写一句。

### 验收

- 三种来源的题都能在「易错题」里看到，且能按状态筛。
- 老库升级后原记录全部落在「做错」，列表条数不变。

## 五、⑧ 拍完即检（P1）

不用模型，纯本地位图指标，**可解释、可单测**：

| 指标 | 判据 | 提示 |
| --- | --- | --- |
| 模糊 | 灰度 Laplacian 方差低于阈值 | 「这张有点糊，重拍一张更准」 |
| 过曝/过暗 | 直方图两端像素占比 | 「光线太强/太暗，避开反光再拍」 |
| 倾斜 | 文本行方向估计，超过 ±8° | 「拍歪了，尽量正对纸面」 |
| 反光 | 高亮连通块面积占比 | 「有一块反光，换个角度」 |

- 位置：裁剪确认页（`PagePreviewScreen`）顶部一条可关闭的提示条，主按钮仍是「用这张」。
- 实现：`ml/CaptureQuality.kt`（纯 Kotlin + `IntArray` 像素，JVM 可测），输入是已缩到
  长边 480 的预览位图，不增加上传体积。
- 不做：不拦截、不强制重拍（老机光照差时误判率高，拦住会让人拍不了题）。

## 六、⑨ 自检示范（P1，含「是什么」的解释）

### 是什么

**自检示范 = 解答卡底部的一小块「怎么验算」，不是再讲一遍解法。**
它取阶段 B 的 `check` 字段（模型已经算了，但现在没露出来），再配 2-3 条可执行动作：
代回原式 / 看量纲与单位 / 取特值或边界。

例：`f(x)=x²-2x+1 在 [0,3] 的最小值`

> **自检**：把 x=1 代回，f(1)=0；再代两端 f(0)=1、f(3)=4，都更大 → 最小值 0 成立
> - 你来试：把 x=3 代进去，算出来是几？
> - 换个数：如果区间改成 [2,3]，最小值会变成多少？

### 流程

    解答完成 → 卡片底部「自检」折叠条（默认收起，避免每张卡都长）
      → 展开：check 原文 + 2 条「你来试」
      → 学生点「我核对过，一致」  → 写 review_log(selfScore=良好, source=CHECK)
      → 学生点「我核出来不一样」  → 自动开追问，预填「我按〈check〉核对，得到 X，和答案不一致」
      → 学生点「跳过」→ 不写任何记录（不打搅，也不污染统计）

### 实现

- `MessageList` 的解答卡底部新增 `SelfCheckCard`（折叠，`AnimatedVisibility` 已有先例）。
- 「你来试」的两条提示由 `SelfCheckPrompts`（纯函数）从 steps/check 里生成，
  不额外调用模型；生成不出就不显示该行。
- 依赖 ④ 的状态字段：点「一致」时把该题 `status` 从 `pending_check` 推向 `mastered` 候选。

## 七、③ 核对计入掌握度（P1）

不改公式，**走已有通道**：

- `mastery = 0.55*复习自评 + 0.30*(1-错题频次) + 0.15*覆盖度`，乘提示折扣。
- 核对一致 → 插一条 `review_log`（`selfScore` 取「良好」，新列 `source='check'`）。
  这条记录本来就算在 0.55 那一项里，因此公式一个字都不用改。
- 核对不一致 → 记一条 `mistake_record`（`status='wrong'`，`source='check'`），
  0.30 那一项自然下降。
- `review_log` 加 `source` 列（DB v4），报告页可把「自评」与「核对」分开统计，
  否则老师/家长看到的分不清是学生自己打的还是核对出来的。

**风险**：核对一次就记「良好」等于一次自我确认就能拉高掌握度。缓解：
- 同一个 kpoint 在同一天只记一次；
- 折扣沿用 `hint_log`：用了提示才核对通过的，仍乘 0.6。

## 八、⑤⑥ 笔记与陪伴总结（P1）

### ⑤ 陪伴总结「可查看 + 可写入知识点树」

- 新表 `study_note`：`id, kpointId?, questionId?, source(companion/check/manual), title, body, createdAt, updatedAt`。
- 陪伴每轮回答结束后，用**受控 ID 抽取**（复用现有「名字命中」启发式，命中不到就不挂）：
  命中 1-3 个 kpoint 就把这条回答存成笔记，`kpointId` 取首个。
- 「写入知识点树」的边界：**只允许挂到已有节点，不允许新增节点**。
  理由：知识点树是掌握度、推荐路径、阶段 D 候选的唯一锚点，自造节点会让这三件事同时失效。
  真要支持新概念，走「候选节点」表等人工确认，不在本轮。
- 查看入口：知识点详情页新增「我的笔记」卡（按 kpointId 查），陪伴页每条气泡右侧加「存为笔记」。

### ⑥ 笔记进回顾与考前资料

- `ReviewMaterialViewModel` 增加 `loadNotes(subjectCode)`，生成资料时单列一节「我的笔记」，
  位置放在「易忘点回顾」之后。
- 首页「考前速览」直接复用这份资料（科目取当前选中），不再另做一套。
- 核心目的写死在文案里：**这些是你自己问过/核过的点，不是系统推的**。

## 九、⑩ 变式过关 + 刷题（P2）

现有基础：`GenerateExerciseUseCase` 已经能生成变式并用「独立重解」校验答案，通过才入库。
缺的是「检索真题」与「过关判定」。

### 联网检索的三条路（需要选一条）

| 方案 | 做法 | 代价 | 风险 |
| --- | --- | --- | --- |
| A. 不真联网（推荐起步） | 模型按薄弱知识点生成 + 自查，多题、分层难度 | 0 新依赖 | 题目新颖度有限 |
| B. 用户自带搜索 Key | Tavily/Serper 检索 → 模型整理题干与答案 | 多一套 Key 与计费 | 教辅站点付费墙、版权、答案错 |
| C. 接题库 API | 付费接口 | 有月费 | 与「无后端」定位冲突 |

**建议**：A 先落地并把「过关」跑通；B 做成设置里的开关（默认关），标注「题目来自公开网页，
答案未经校验，仅供参考」。

### 刷题流程（按你的要求：先作答，后给答案）

    选薄弱点（掌握度 <60 或最近错过） → 出 3 题（一次一题）
      → 学生输入答案 → 「看答案」（只展示，不判断对错）
      → 与答案不一致/不会 → 「问一句」直接进追问（带本题上下文）
      → 三题里有 2 题自评「对上了」→ 该 kpoint 记为「已过关」，写 review_log

## 十一、① 引擎与联网化（P2，含一处事实纠正）

- **sherpa-onnx 是语音识别（ASR/TTS）框架，不做 OCR。** OCR 的同类开源方案是
  PaddleOCR / RapidOCR（ONNX）。因此这一项有两种读法，需拍板：
  - 读法 A（推荐）：**语音**换成本地 sherpa-onnx（离线、免费、国产 ROM 也能用），
    OCR 继续走视觉模型；
  - 读法 B：真要换 OCR 引擎 → 选 RapidOCR/PaddleOCR，sherpa-onnx 不参与。
- 代价（读法 A）：模型文件 40-80MB 需首次下载或内置；低端机首帧慢；
  中文流式识别要接 VAD 分段。
- **联网化小改动**（与 ⑭ 的 A 方案一致）：
  启动时检查「网络 + Key」，首页顶部一条状态条；无网时拍题页禁用发送并给「去联网」CTA；
  易错题、知识点、笔记仍然纯本地可用。**不做后端、不做账号。**
