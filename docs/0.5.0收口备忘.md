## 一、范围

十四项需求分三批完成，数据库 v1 → v3。

### P0：拍题主路径与观感

| 项 | 结果 | 关键取舍 |
| --- | --- | --- |
| 输入区改版 | 左键切语音/键盘，中间是输入框或大块「按住 说话」，右侧相机 + 更多 | 相机回到常驻位，相册进菜单 |

| 识别引擎 | 设置里可选，默认非 Google 厂商引擎；断网自动切离线并重试一次 | 引擎偏好存 SharedPreferences，不进 Room |
| 启动页 | 淡紫底 + ToTop 五个字母逐个淡入，最短展示 700ms | 窗口底色与 `Tokens.Splash` 同色，冷启动不再黑屏 |

    ./gradlew :app:compileDebugKotlin :app:ktlintCheck
    ./gradlew :app:detekt :app:testDebugUnitTest

## 五、发布到 GitHub

已发布：<https://github.com/Ky-l0r/ToTop/releases/tag/v0.5.0>

- Release 名：`0.5.0`，标签 `v0.5.0`，指向 `caae57a`（含版本号与本文档）；
- 附件：`app-release-0.5.0.apk`，15.7 MB，release keystore 签名，
  SHA-256 指纹 `c0187155…82dbe2`；
- 仓库规范禁止把 APK 提交进仓库（`*.apk` 已在 `.gitignore`），因此只作为 Release 附件。

### 发布过程记录（含两次返工）

1. 本机没有 `gh`，也没有 `GH_TOKEN`，改用 `curl` 直接调 GitHub API；
2. `curl` 与本机 `git` 遇到同一个证书吊销检查问题，
   加 `--ssl-no-revoke` 后可用（与 `git -c http.sslBackend=schannel` 同一个根因）；
3. **标签一开始打在 `1b8915b`**（打包提交）上，而版本号与本文档在 `caae57a`，
   出现「标签里的源码写着 0.4.0、附件却是 0.5.0」的问题，因此把 `v0.5.0` 移到 `caae57a`；
4. 删除远端标签时 GitHub 会把对应 Release **自动转成草稿**，
   移完标签后用 `PATCH /releases/<id>` 以 `draft:false` 重新发布。

正确顺序应该是：先提交版本号与文档，再打标签、再建 Release。
下次发布按这个顺序走，就不需要移动标签。

### 以后再发一次的命令

    # 1. 先提交，确保工作区干净
    git status --short
    # 2. 打标签并推送（标签要打在包含版本号的提交上）
    git tag v0.x.y <commit>
    git -c http.sslBackend=schannel push origin refs/tags/v0.x.y
    # 3. 建 Release 并上传附件（令牌只放环境变量，不落盘）
    curl -s --ssl-no-revoke -u "$GH_USER:$GH_TOKEN" \
         -H "Accept: application/vnd.github+json" -H "Content-Type: application/json" \
         -X POST https://api.github.com/repos/Ky-l0r/ToTop/releases \
         -d '{"tag_name":"v0.x.y","name":"x.y.z","body":"见 docs 收口备忘"}'
    curl -s --ssl-no-revoke -u "$GH_USER:$GH_TOKEN" \
         -H "Content-Type: application/vnd.android.package-archive" \
         -X POST --data-binary @app/build/outputs/apk/release/app-release.apk \
         "https://uploads.github.com/repos/Ky-l0r/ToTop/releases/<id>/assets?name=app-release-x.y.z.apk"
