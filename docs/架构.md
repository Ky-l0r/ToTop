# 架构设计

本文描述 To Top 的整体架构、分层职责、核心链路与关键约束。
实施依据为《AI 辅助学习 App 开发方案》，本文不重复产品需求，只说明工程如何落地。

## 一、总体形态

单模块 Android 应用，无自建后端。数据默认不出设备，唯一网络出口由用户自己的 API Key 直连模型厂商。

    用户设备
    ┌─────────────────────────────────────────────────────────┐
    │  UI 层      Compose 页面 + ViewModel + StateFlow          │
    │  领域层     UseCase 与纯算法（掌握度、排期、路径、错因）    │
    │  数据层     Room（本地唯一数据源）| LLM 客户端 | 加密存储  │
    │  识别层     ML Kit OCR -> 图片预处理 -> 模型路由 -> TTS   │
    └────────────┬───────────────────────────┬────────────────┘
                 │ 本地：识别、压缩、缓存、统计、公式、导出、备份
                 │                                   │ 用户 Key 直连
                 ▼                                   ▼
        本机 SQLite 与图片目录              模型厂商 OpenAI 兼容端点
        （数据不出手机）                   （Qwen-VL / DeepSeek / Ollama）

设计上的三条硬约束决定了大量细节：

1. 无后端，因此不存在会话同步、账号迁移、服务端缓存，全部状态落本机。
2. 成本由用户承担，因此任何新增调用都必须可关闭、可缓存、可取消，并在界面上显示用量。
3. 目标机型为中低端老机，因此禁用毛玻璃与大动画、图表关动画、图谱预计算坐标、列表分页。

## 二、分层与依赖方向

依赖方向自上而下，禁止反向依赖：

| 层 | 包路径 | 职责 | 禁止事项 |
| --- | --- | --- | --- |
| 界面层 | `ui/` | Compose 页面、ViewModel、状态流 | 禁止直接访问 Room，禁止直接调用 Retrofit |
| 领域层 | `domain/` | 领域模型、DTO 契约、纯算法 | 禁止依赖 Android SDK，保证可在 JVM 单测 |
| 数据层 | `data/` | Room、DAO、Repository、网络、加密存储 | 禁止向上返回实体对象，必须转为领域模型 |
| 识别层 | `ml/` | OCR、图片预处理、模型路由、TTS | 禁止在此发起业务决策 |
| 后台任务 | `work/` | 日汇总、重试、缓存清理 | 禁止高频轮询 |
| 工具 | `util/` | 导出、备份、图片编码、时间源 | 禁止放置业务规则 |

## 三、核心链路：对话式解题

方案要求三阶段拆分，禁止在同一次调用里既解题又找错，否则会被学生的错误思路带偏。
实际实现为四个阶段调用，中间穿插本地计算与缓存判定。

    [1] 用户拍照 + 描述自己的解题过程
    [2] 图片预处理：长边 <= 1280，JPEG 质量 0.78，旋转纠正，存本机，算 sha256
    [3] 缓存判定：sha256 + 提示词版本 + 模型名，命中则直接读本地，0 token
    [4] 离线 OCR：ML Kit bundled，返回文本、平均置信度、是否含图形
    [5] 模型路由：印刷体且置信度 >= 0.80 且无图形 -> 纯文本模型
                 否则（手写、含图、置信度低）    -> 视觉模型
    [6] 阶段 A 结构化识题：题干、已知、所求、选项、是否含图
    [7] 阶段 B 独立求解：只给题目，不给学生过程
    [8] 阶段 C 错因定位：学生步骤与标准步骤对齐，找出第一个错误步骤
    [9] 阶段 D 知识点抽取：只能映射内置知识点树的受控 ID
    [10] 落库：题目、错题记录、知识点关联、调用留痕
    [11] 流式回传：按到达顺序渲染步骤卡、错因卡、知识点卡
    [12] 失败降级：校验失败重试 1 次，仍失败则提示用户，绝不写入脏数据

阶段隔离的工程含义：阶段 B 的输入结构体里根本没有学生过程字段，不是靠提示词约束，
而是在代码层面物理隔离，避免未来有人误传。

## 四、模型路由与成本控制

| 输入特征 | 路由 | 单次量级 | 说明 |
| --- | --- | --- | --- |
| 置信度 >= 0.80、纯印刷体、无图形 | 纯文本模型 | 1.5K 至 3K token | 成本最低，覆盖多数场景 |
| 手写、含几何或函数图、置信度低 | 视觉模型 | 3K 至 8K token | 图片按 tile 计费，已前置压缩 |
| 同一 sha256 二次打开 | 本地缓存 | 0 | 内存 LRU 与 Room 双层 |
| 知识点查询、公式朗读、图表统计 | 纯本地 | 0 | 不发起请求 |
| 周报 AI 解读（可关闭） | 纯文本模型 | 约 0.8K | 默认仅模板渲染 |

落实手段：

- 图片压缩前置，统一 JPEG，不用 WebP 以规避厂商兼容问题
- 双层缓存，键为图片 sha256 + 提示词版本 + 模型名
- 上下文极简，每次只发当前题目，需要上下文时用一句话摘要
- 设定输出上限，提供简洁与详细两档
- 页面离开即取消进行中的 Call
- 读取响应中的用量字段并显示，让用户自己掌握花费

## 五、本地数据模型

Room 为唯一数据源，表结构与方案第五章一致。核心表与关系：

| 表 | 主键 | 关键约束 |
| --- | --- | --- |
| question | id | imageSha256 唯一，作为缓存与去重锚点 |
| mistake_record | id | 外键指向 question，记录首个错误步骤与错因 |
| knowledge_point | id | 受控 ID，种子数据装载 |
| kpoint_edge | (fromId, toId, type) | 前置、相关、扩展三类边，入库前环检测 |
| mistake_kpoint | (mistakeId, kpointId) | 多对多，双索引供掌握度聚合 |
| review_log | id | 复习自评记录，驱动间隔重复 |
| hint_log | id | 提示解锁记录，参与掌握度折扣 |
| mastery | kpointId | 掌握度与近 90 天历史快照 |
| daily_stats | (date, subject) | 日汇总，禁止实时全表扫描 |
| report | id | 周报与月报，统计 JSON 与 AI 解读分开存 |
| ai_trace | id | 每次调用的模型、用量、耗时、成功标志 |
| settings | key | 偏好设置 |
| outbox | id | 离线写队列 |
| cache_entry | (sha256, promptVer, model) | 结果缓存，按最近访问淘汰 |

统一约定：时间戳一律存 UTC 毫秒，展示层转本地时区；所有表结构变更必须配迁移测试与 schema 快照。

## 六、掌握度计算

不使用正确率。掌握度完全本地计算，纯 Kotlin 实现，可单测：

    mastery(k) = clamp01(
        0.55 * 复习自评加权分        # 近 14 天权重 x1.5，按指数衰减
      + 0.30 * (1 - 归一化错题频次)  # 近 30 天错题越少越高
      + 0.15 * 覆盖度                # 该知识点练习是否充分
    ) * 提示折扣                     # 全靠提示才想通 x0.6，自主想通 x1.0

每日由后台任务重算并留存快照。色阶固定为红（低于 40）、黄（40 至 70）、绿（高于 70），
全应用通过统一函数取色，禁止页面内自定义。

## 七、知识图谱与推荐路径

- 节点与边来自内置种子数据，AI 只能映射既有 ID，不得自造
- 前置边必须人工整理，AI 建议不自动生效
- 入库前做环检测（深度优先三色标记），出现环则拒绝写入并记录日志
- 渲染使用预计算坐标 + 静态渲染 + 缩放平移，单屏节点不超过 80，分层展开
- 推荐路径以目标节点为终点沿前置边反向搜索，收集掌握度低于 60 的前置节点并拓扑排序

## 八、网络层

- 全部走 OpenAI 兼容的 `/chat/completions`，支持流式
- 连接超时 15 秒，读超时 120 秒
- 每次请求携带客户端幂等 ID，避免重试重复计费
- 失败按 1 秒、2 秒、4 秒退避重试，最多 3 次，仅对幂等请求
- 页面销毁取消 Call；取消后拒绝新调用
- 每次调用写留痕表，设置页可查看近 30 天用量
- 错误分类明确：Key 无效、余额不足、网络不通、模型名错误、Base URL 错误，禁止笼统报「请求失败」

## 九、密钥与隐私

- API Key 使用 Android Keystore 支撑的加密存储，唯一明文出现位置是请求头
- 日志与错误信息中必须屏蔽该请求头
- 应用关闭系统云备份与设备迁移的数据采集
- 导出与备份走 SAF 与 FileProvider，遵守分区存储
- 图片保存在应用私有目录，不写入公共相册（除非用户显式导出）

## 十、性能设计

| 维度 | 做法 | 禁止 |
| --- | --- | --- |
| 公式渲染 | assets 内置 KaTeX，WebView 实例复用 | 每题新建 WebView，使用 MathJax |
| 长列表 | 分页查询、图片懒加载、缩略图 | 一次查全表、原图进列表 |
| 动画 | 仅淡入淡出与必要的状态切换 | 毛玻璃、视差、大面积弹性动画 |
| 图表 | canvas 渲染、关闭动画、降采样至 60 点以内 | 大量 SVG 节点、带动画的复杂图表 |
| 图谱 | 预计算坐标、静态渲染 | 运行时力导向计算 |
| 内存 | Bitmap 及时回收，图片缓存设上限 | 无上限缓存、大图常驻 |
| 存储 | 结构化数据一律进 Room | 把大 JSON 塞进 SharedPreferences |
| 包体 | R8 全量、资源压缩、仅 arm64 | 未混淆、多 ABI 全打 |
| 后台 | 每日一次，充电且空闲执行 | 前台轮询、高频定时器 |

## 十一、目录结构

    app/src/main/java/com/totop/app/
      App.kt                应用入口，完成依赖注入初始化
      MainActivity.kt       唯一 Activity，承载 Compose
      navigation/           路由常量、底部导航、导航宿主
      ui/                   页面与主题，页面一律以 Screen 结尾
      domain/               领域模型、DTO 契约、纯算法
      data/local/           Room 数据库、实体、DAO、种子装载
      data/remote/          模型客户端、请求构造、错误映射、缓存
      data/repo/            Repository，屏蔽本地与远端差异
      data/prefs/           设置与加密密钥存储
      ml/                   识别、预处理、模型路由、语音
      work/                 后台任务
      util/                 导出、备份、编码、时间源
    app/src/main/assets/
      prompts/              四阶段提示词与版本号
      seed/                 知识点树、关系边、易错点、口语化规则
      graph_layout/         图谱预计算坐标
      katex/                公式渲染资源（计划中，M2 引入）
    docs/                   架构、接口契约、提示词规范、测试清单

## 十二、里程碑与架构演进

| 里程碑 | 架构增量 |
| --- | --- |
| M1 | 骨架、依赖注入、导航、主题、加密存储、流式客户端、留痕 |
| M2 | 相机、图片预处理、离线识别、模型路由、四阶段编排、流式渲染 |
| M3 | 错题本查询与筛选、复发计数 |
| M4 | 掌握度算法与图表、知识点详情、复习自评、间隔重复 |
| M5 | 日汇总任务、周报模板、三档引导模式、系统 TTS |
| M6 | 图谱环检测、预计算坐标渲染、推荐路径、解锁机制 |
| M7 | 导出、SAF 写入、备份与恢复 |
| M8 | Baseline Profile、R8 调优、真机实测、发布流水线 |

架构演进原则：新增能力优先复用既有层，不新增第四种数据源；任何跨层捷径都视为架构缺陷。
