# 部署与运维

## 1. 服务器与资源

| 用途 | 建议规格 | 说明 |
| --- | --- | --- |
| 应用服务器 | 2 核 4G，40G SSD，5M 带宽 | FastAPI + Nginx + Redis 同机；国内轻量服务器即可起步 |
| 数据库 | 同机 Docker PostgreSQL，或用云数据库 | 数据量小（单用户几十次考试），同机够用；生产建议托管版做自动备份 |
| 对象存储 | 阿里云 OSS / 腾讯云 COS / 自建 MinIO | 试卷与答题卡图片，**不要放在应用服务器磁盘** |
| 模型 | 阿里云百炼 Qwen-VL | 按量付费，无需自建 GPU |

成本量级（需按实际询价核实）：轻量服务器每月几十元 + 对象存储与流量几元 + 短信按条计费 + 模型按 token 计费。**模型费用是唯一随用户量线性增长的主要成本项**，见 [03-AI分析链路](03-AI分析链路.md) 第 6 节。

## 2. 域名与合规（上架前必须完成）

1. **域名注册** + **ICP 备案**（工信部，通常 7~20 个工作日，需国内服务器）
2. **公安联网备案**（ICP 备案通过后 30 日内）
3. **App 备案**（工信部 App 备案系统，2023 年起强制，未备案的应用商店不予上架）
4. **HTTPS 证书**（可用云厂商免费证书或 Let's Encrypt）
5. **隐私政策与用户协议**页面（应用内可访问，且需在应用商店资料中填写链接）
6. **AI 生成内容相关要求**：若对外提供生成式 AI 服务，需关注算法备案/安全评估要求（以主管部门最新口径为准，建议咨询合规服务商）

## 3. Docker Compose 部署

`services/api/docker-compose.yml`：

```yaml
services:
  api:
    build: .
    env_file: .env
    ports:
      - "127.0.0.1:8000:8000"
    depends_on:
      - db
      - redis
    restart: unless-stopped

  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: totop
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: totop
    volumes:
      - pgdata:/var/lib/postgresql/data
    restart: unless-stopped

  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redisdata:/data
    restart: unless-stopped

volumes:
  pgdata:
  redisdata:
```

启动：

```bash
docker compose up -d --build
docker compose exec api python scripts/seed.py     # 可选：演示数据
```

## 4. Nginx 反向代理

```nginx
server {
    listen 443 ssl http2;
    server_name api.example.com;

    ssl_certificate     /etc/nginx/ssl/fullchain.pem;
    ssl_certificate_key /etc/nginx/ssl/privkey.pem;

    # 试卷与答题卡是多页高清图片，必须放开上传体积
    client_max_body_size 50m;
    client_body_timeout  120s;

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 180s;      # AI 分析是异步任务，轮询接口无需长超时，但上传后的同步处理会给足余量
    }

    location /static-uploads/ {
        alias /var/www/uploads/;      # 仅本地存储模式使用；生产建议改用对象存储直传
    }
}

server {
    listen 80;
    server_name api.example.com;
    return 301 https://$host$request_uri;
}
```

## 5. 对象存储（生产推荐直传）

流程：客户端向 `POST /uploads/presign` 申请预签名 URL → 客户端**直接 PUT 到 OSS/COS** → 只把 `object_key` 交给后端。

好处：图片不经过应用服务器，省带宽、省内存、可断点续传。

安全要点：

- Bucket 设为**私有**，前端展示时用短时效预签名 GET URL
- 限制单文件大小（建议 ≤ 20MB）与 MIME 类型白名单（jpeg/png/webp/pdf/docx）
- object_key 用 `{user_id}/{yyyyMM}/{uuid}.{ext}` 结构，便于按用户清理
- 用户删除考试时，异步清理对应对象

## 6. 短信验证码

1. 开通阿里云/腾讯云短信服务，申请**签名**与**模板**（需 1~3 个工作日审核）
2. `.env` 配置 `SMS_ACCESS_KEY_ID` / `SMS_ACCESS_KEY_SECRET` / `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE`
3. **必须设置 `SMS_DEV_MODE=false`**，否则验证码会回显给任何人
4. 防刷：同手机号 60 秒 1 条、同 IP 每小时 10 条、同手机号每天 10 条（Redis 计数）
5. 验证码存 Redis，5 分钟过期，校验成功后立即删除

## 7. 环境变量（`.env`）

```ini
# 基础
APP_ENV=production
SECRET_KEY=<openssl rand -hex 32 生成，务必与开发环境不同>
DATABASE_URL=postgresql+asyncpg://totop:密码@db:5432/totop
REDIS_URL=redis://redis:6379/0

# AI
AI_PROVIDER=qwen                 # qwen | mock
DASHSCOPE_API_KEY=sk-xxxx
QWEN_MODEL=qwen-vl-max

# 存储
STORAGE_PROVIDER=local           # local | s3
S3_ENDPOINT=https://oss-cn-hangzhou.aliyuncs.com
S3_BUCKET=totop-uploads
S3_ACCESS_KEY_ID=xxx
S3_ACCESS_KEY_SECRET=xxx

# 短信
SMS_DEV_MODE=false
SMS_SIGN_NAME=ToTop
SMS_TEMPLATE_CODE=SMS_123456789

# 计费
ANALYSIS_COST_CREDITS=1
ADS_PER_CREDIT=10
```

> `.env` 已在 `.gitignore` 中；**绝不要把密钥提交进 Git**，也不要把 key 打进客户端包体。

## 8. 备份与监控

| 项 | 做法 |
| --- | --- |
| 数据库备份 | `pg_dump` 每日全量 + 保留 14 天，异地存一份；上线前演练一次恢复 |
| 对象存储 | 开启版本控制或生命周期规则，误删可恢复 |
| 日志 | 应用日志按天切割；关键事件（扣费、退款、分析失败、支付回调）必须落结构化日志 |
| 告警 | 模型调用失败率、分析平均耗时、点数余额异常波动、磁盘使用率 |
| 健康检查 | `GET /health` 接入云监控拨测 |
